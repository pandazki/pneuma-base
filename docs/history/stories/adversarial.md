# Pneuma Base 对抗性用户故事

这份文件用来检验领域模型。每个故事里都有东西出岔子、两个写者撞车，或者落在边界上。顺利使用的故事在另一份文件里。

每个故事只写发生了什么，以及模型必须给出唯一答案的问题。这里不给答案。

---

## 一、在工具之外改动

### 1. 在 Finder 里同时移动、改名、改内容

情形：库里的《竞品对比.md》放在“研究/”下。agent 在 11 月 3 日的场景里读了三份带进来的行业报告，然后做出了它。

经过：
1. 11 月 10 日，人在 Finder 里把它拖进“写作/”，改名为《Q4 竞品-终稿.md》。
2. 同一分钟，人在编辑器里打开它，删掉后半篇，补了两段自己写的结论，然后保存。
3. 这期间没有任何 agent 会话，也没有运行任何 Pneuma Base 的软件。
4. 11 月 12 日，Codex 在新会话里按名字查找“竞品对比”，又按文字查找人补的结论里的一句话。

要回答的问题：
- 《Q4 竞品-终稿.md》和原来的《竞品对比.md》是不是同一个条目？
- 它现在的来历是什么？人补的两段算在哪个场景名下？
- 11 月 3 日那张场景卡上“做了哪些”一栏，现在指向什么？
- 两次查找各返回什么？

### 2. agent 直接写盘，什么都没记

情形：Codex 拿到了库的技能，也读过说明。在一次赶工的会话里，它直接用自己的写文件工具往“网站/”下写了 12 个文件，没有记录场景。

经过：
1. 12 个文件里有 9 个是新文件，3 个和已有条目同名，直接覆盖了原文件。
2. 被覆盖的 3 个原本都有清楚的来历，分别来自三个不同的旧场景。
3. 会话结束。Codex 的对话原文还在它自己的目录里。
4. 第二天，Claude Code 在另一个会话里打开这个库，准备基于其中一个被覆盖的文件接着做。

要回答的问题：
- 9 个新文件现在的来历是什么？库能不能把它们和 Codex 那次会话对上？凭什么对上？
- 被覆盖的 3 个，是原条目的新版本，还是原条目没了、出现了新条目？覆盖前的内容在库里还有没有？
- 在有人补上来历之前，Claude Code 读了它们、又做出新东西，新东西的来历怎么记？

### 3. 整个子文件夹被重新整理

情形：“研究/”下原本按客户分成 6 个子文件夹，共 800 个文件。“研究/客户A/”是一个区域，授权给了一个专门服务客户A 的 agent。

经过：
1. 周末，人在 Finder 里把这 800 个文件按年份放进“研究/2024/”“研究/2025/”“研究/2026/”。原来的 6 个子文件夹（包括“客户A/”）被清空后删掉。
2. 整理时，人顺手给 40 个文件改了名，又删掉了 15 个他认为重复的文件。
3. 周一，持有“客户A”授权的 agent 开始一次会话。
4. 同一天，人打开查看器看最近 30 个场景。

要回答的问题：
- 800 个文件里，哪些还是原来的条目？库凭什么认出它们？
- “客户A”区域还存在吗？那份授权现在覆盖哪些文件？
- 旧场景卡里写的位置还能不能把人带到文件？查看器里这些场景显示什么？
- 被删掉的 15 个“重复”文件，在库里算删除还是合并？

## 二、读了却没留下痕迹

### 4. agent 自己翻了资料，只记了做出来的东西

情形：Claude Code 接到“写一份定价建议”的任务。库里有 300 份带进来的资料。

经过：
1. 它在库里按文字查找“定价”，结果有 40 条，每条带一小段摘录。
2. 它用自己的读文件工具打开了其中 5 份，没有告诉库。
3. 它又打开了项目目录里一份不在库里的《成本表.xlsx》。
4. 它把《定价建议.md》放进库，并记下了场景：要解决的事、哪个 agent、做了什么。“读了哪些”一栏是空的。
5. 一周后，人改了那 5 份中的一份。

要回答的问题：
- 《定价建议.md》的来历里有没有那 5 份？有没有只在搜索结果里看过摘录的另外 35 份？有没有库外的《成本表.xlsx》？
- 5 份中的一份改了以后，《定价建议.md》会不会被标成可能过期？
- 这张“读了哪些”为空的场景卡，算完整的记录，还是需要有人来补的记录？

### 5. 读的东西根本不在库里

情形：一次会话里，agent 读了三样东西：一个网页、人在对话里粘贴的一段话、另一个项目目录里的一份设计稿。它基于这三样做出《技术选型.md》，放进了库。

经过：
1. agent 记下场景，把三样东西都写进“读了哪些”。
2. 它没有把网页、那段话或设计稿带进库。
3. 两周后，那个网页改版了。那个项目目录被删了。
4. 按设置，这次会话的整段对话只留了引用，没有复制。

要回答的问题：
- 场景卡里“读了”一个不是条目的东西，它在库里算什么？有没有身份？能不能被查找到？
- 网页改版后，《技术选型.md》会不会被标成可能过期？库靠什么知道网页变了？
- 那段粘贴的话只存在于对话原文里。原文不在了以后，《技术选型.md》的来历里还剩什么？

## 三、装不进一个格子的会话

### 6. 会话崩溃，三天后又被恢复

情形：11 月 1 日，Claude Code 的会话已经记下“读了 A、B”，正在把《调研报告.md》写进库。写到一半，电脑断电。

经过：
1. 磁盘上留下半份《调研报告.md》。这个场景没有收尾。
2. 11 月 2 日，Codex 在另一个会话里看到这半份报告，补完了后半部分，记在自己的场景里。
3. 11 月 4 日，人用 Claude Code 恢复了 11 月 1 日那个会话（同一个会话标识）。它不知道 Codex 做过什么，从断点接着写，覆盖了报告的后半部分。
4. 它接着又做出《摘要.md》，然后正常收尾。

要回答的问题：
- 11 月 1 日和 11 月 4 日是一个场景还是两个？场景卡上的时间写什么？
- 《调研报告.md》是哪个场景做出来的？Codex 补的后半部分被覆盖之后，记录里还算不算 Codex 做过它？
- 11 月 1 日到 4 日之间，有人查看这个场景时，看到它处于什么状态？

### 7. 一次会话同时在两个库里干活

情形：人有“工作库”和“个人库”两个库。一次会话里，agent 从个人库读了《我的写作习惯.md》，在工作库里做出了《客户邮件模板.md》。

经过：
1. agent 先在个人库里记下“读了《我的写作习惯.md》”。
2. 然后在工作库里记下“做了《客户邮件模板.md》”。
3. 一个月后，人把个人库整个搬到外接硬盘上，然后拔掉了硬盘。
4. 同事用工作库的一份授权，打开了《客户邮件模板.md》的场景卡。

要回答的问题：
- 这次会话在两个库里各有一张场景卡，还是只在一个库里有？
- 《客户邮件模板.md》的来历会不会提到个人库里的条目？如果会，同事看到的是什么？
- 个人库不在了以后，工作库里这条来历处于什么状态？

### 8. 一次会话做了两件不相干的事

情形：人一早开了一个会话。上午让 agent 修好了网站的样式，下午在同一个会话里让它写了一张生日贺卡。两样都放进了库。

经过：
1. 上午：agent 读了《品牌色.md》，改了“网站/官网/”里的样式文件。
2. 下午：agent 读了一张带进来的家庭照片，做出《生日贺卡.png》。
3. 库按规则把同一次会话里的东西关联成一组。
4. 一个月后，《品牌色.md》改了。人在查看器里看“官网”这条线索。

要回答的问题：
- 《生日贺卡.png》算不算“官网”这条线索的一部分？
- 《品牌色.md》改了以后，《生日贺卡.png》会不会被标成可能过期？
- 人能不能把这个场景拆成两个？拆了的话，之前记下的读和做各归哪一边？拆分本身记在哪里？

### 9. 主 agent 派了四个子 agent

情形：Claude Code 接到“整理竞品资料”的任务，派出 4 个子 agent。每个子 agent 有自己的对话原文和会话标识。

经过：
1. 子 agent 1 和 2 各读了库里 20 份资料。它们没有直接碰库，只把摘要回报给主 agent。
2. 子 agent 3 用同一份授权，直接把《竞品清单.csv》写进库，并记下了一个场景。
3. 子 agent 4 中途失败，在库里留下一个半成品文件。
4. 主 agent 汇总后做出《竞品报告.md》，记下场景。它的“读了哪些”一栏只列了《竞品清单.csv》。

要回答的问题：
- 这是一个场景还是五个？子 agent 3 记下的场景和主 agent 的场景是什么关系？
- 《竞品报告.md》的来历里有没有子 agent 1、2 读过的那 40 份？
- 子 agent 4 留下的半成品是什么状态？记在谁名下？
- 场景卡上“哪个 agent”一栏写什么？

### 10. 整段对话已经被清理

情形：库里有一个 8 月的场景，当时只留了整段对话的引用，没有复制。Claude Code 默认在 30 天后清理旧对话。

经过：
1. 9 月中旬，那段对话原文被自动清理。
2. 11 月，人在查看器里打开 8 月那个场景，想知道当时为什么做了《迁移方案.md》。
3. 同一个库里，另一个 8 月的场景当时打开了“复制一份”的开关，它的对话原文还在库里。
4. 人从此把“复制一份”的开关全部打开。

要回答的问题：
- 引用失效以后，这个场景还算完整吗？库会不会发现引用失效？发现了怎么显示？
- 引用失效和来源条目变了（可能过期）是不是同一种状态？
- 开关打开以后，对还在进行、以后还会继续变的会话，库里复制的是哪个时刻的对话？

## 四、多个写者同时写

### 11. 两个 agent 在同一分钟

情形：Claude Code 和 Codex 在同一台机器上各开着一个会话，都在用同一个库。

经过：
1. 10:00，Claude Code 读了《需求说明.md》。
2. 10:30，Codex 改写了《需求说明.md》的第三节，并记下了场景。
3. 11:00，Claude Code 凭它 10:00 读到的内容做出《设计稿.md》，记下场景：“读了《需求说明.md》”。
4. 也在 11:00 的同一秒，两个 agent 都从同一个网址抓下了价格页，都存成“资料/”下的《pricing.html》。两份内容只差一个时间戳。

要回答的问题：
- 《设计稿.md》是否可能过期？它的来历指向《需求说明.md》的哪个版本？
- 磁盘上只剩一个《pricing.html》。库里有一个条目还是两个？记录上是谁带进来的？
- 两张场景卡在同一秒写入，会不会有一张丢失，或者被另一张改掉？

### 12. 两台机器各自离线修改，再同步

情形：人在笔记本和台式机上用同步插件双向同步同一个库。整个周末两台机器都没联网。

经过：
1. 笔记本上：人把《产品路线图.md》改名为《2027 路线图.md》；一个 agent 读了它，做出《季度目标.md》。
2. 台式机上：另一个 agent 改写了《产品路线图.md》的第二节，又基于它做出《招聘计划.md》。
3. 台式机上，人删掉了《旧会议纪要.md》。笔记本上，一个 agent 正好读了它，做出《决策清单.md》。
4. 周一两台机器联网，同步插件开始同步。

要回答的问题：
- 同步完成后，路线图是一个条目还是两个？叫什么名字？内容是哪个版本？
- 《季度目标.md》和《招聘计划.md》分别来自路线图的哪个状态？哪一个会被标成可能过期？
- 《旧会议纪要.md》一边被删、一边被读，同步后它还在不在？《决策清单.md》的来历怎么显示？
- 两边各自追加的管理日志合在一起时，先后顺序依据什么？

### 13. 同步时记录和文件不同时到

情形：同步插件总是先传小文件。一个 agent 在台式机上做出一段 2GB 的视频《发布会.mp4》，并记下了场景。

经过：
1. 场景卡几秒钟就到了笔记本，视频还要一个小时才到。
2. 这一小时里，笔记本上的另一个 agent 看到场景卡提到《发布会.mp4》，找不到文件，就自己剪了一个同名视频放在同一个位置。
3. 同一时间，反方向：笔记本发往台式机的 30 个新文件到了，但它们的场景卡因为网络中断没到。
4. 台式机上，人看到这 30 个来历不明的文件，手动给它们补上了来历。
5. 第二天，那些场景卡终于到了台式机。

要回答的问题：
- 视频还没到的那一小时里，笔记本上的《发布会.mp4》这个条目处于什么状态？
- 笔记本上自己剪的同名视频和后来到达的原视频，在库里是一个条目、两个条目，还是冲突？
- 场景卡到达以后，人手补的来历和场景卡里的来历同时存在吗？哪一个算数？

## 五、身份

### 14. 同一份合同出现了三次

情形：3 月，一次会话把下载目录里的《合同.pdf》带进了“法务/”。6 月，另一次会话把邮件附件里一份逐字节相同的《合同.pdf》带进了“客户B/”。

经过：
1. 两次带进来分别记在两个场景里。
2. 7 月，人在 Finder 里复制了“法务/”里的那份，得到《合同 副本.pdf》，并在副本上加了批注。
3. 8 月，一个会话读了“客户B/”里的那份，做出《条款摘要.md》。
4. 9 月，“法务/”里的那份被换成了对方返回的签字版。

要回答的问题：
- 这是几个条目？
- 6 月那次会话，在场景卡里算“带进来”还是“读了”？3 月和 6 月两个场景因为这份合同算不算同一条线索？
- 《合同 副本.pdf》的来历是什么？
- 9 月换成签字版以后，《条款摘要.md》会不会被标成可能过期？

### 15. 同名不同物：在 Finder 里点了“替换”

情形：“需求/”下有客户甲的《需求.docx》。已经有 6 样做出来的东西来自它。

经过：
1. 人把客户乙发来的《需求.docx》拖进同一个文件夹。Finder 问是否替换，人点了“替换”。
2. 两份文件内容完全不同，来自不同的客户。
3. 第二天，一个 agent 读了“需求/”下的《需求.docx》，做出《乙方报价.md》。
4. 一周后，人才发现客户甲那份被覆盖了。他从邮件里找回原件，改名为《需求-甲.docx》放回同一个文件夹。

要回答的问题：
- 替换之后，这是同一个条目的新版本，还是原条目没了、出现了一个新条目？
- 那 6 样来自客户甲的东西现在处于什么状态？
- 《需求-甲.docx》放回去以后，和原来的条目是什么关系？那 6 样东西的来历指向哪里？

### 16. 一份拆成两份，两份合成一份

情形：库里有一份 200 页的《研究笔记.md》，已有 4 样做出来的东西来自它。库里还有《周一纪要.md》和《周三纪要.md》两份会议纪要，有 2 样东西来自《周一纪要.md》。

经过：
1. agent 在一个会话里把《研究笔记.md》拆成《研究笔记-上.md》和《研究笔记-下.md》，删掉原文件，并记下了场景。
2. 人在编辑器里把两份纪要手工合并成《本周纪要.md》，然后在 Finder 里删掉了原来两份。这件事没有任何会话。
3. 一个新会话按名字查找“周一纪要”。

要回答的问题：
- 上、下两份是新条目，还是原条目的延续？来自原《研究笔记.md》的 4 样东西现在指向哪里？算不算可能过期？
- 《本周纪要.md》是新条目，还是两份纪要之一的延续？它的来历是什么？
- 查找“周一纪要”返回什么？

### 17. 一个条目是 3000 个文件的目录

情形：“网站/官网/”在库里是一个条目，里面有 3000 个文件，声明了有版本、可部署。

经过：
1. 一个会话只读了其中的《index.html》，做出了《首页文案审阅.md》。
2. 另一个会话改了其中一个样式文件。
3. 人在 Finder 里把其中的“图片/”子文件夹拖出来，放到“素材/”下。
4. 又一个会话在“网站/官网/”里新建了 50 个文件。

要回答的问题：
- 只改了一个样式文件，这个条目算不算有了新版本？《首页文案审阅.md》会不会被标成可能过期？
- 第一个会话算读了整个条目，还是读了一个文件？目录里的一个文件能不能被单独当作条目引用？
- 被拖出来的“图片/”现在是新条目、原条目的一部分，还是别的？
- 新建的 50 个文件属于这个条目，还是各自是新条目？

### 18. 条目只是一个链接，或者大到放不进来

情形：库里有两样东西的本体在库外：一个指向在线文档的链接《团队周报（在线）》，和外接硬盘上 400GB 的原始素材《拍摄素材-2026春》。

经过：
1. 一个会话读了在线文档，做出《月度总结.md》。另一个会话读了素材的一部分，做出《粗剪.mp4》。
2. 同事改了在线文档的内容。一个月后，同事把它删了，链接打开显示 404。
3. 人换了一块新硬盘，把素材拷过去。硬盘的挂载名从“T7”变成了“T9”。

- 一个场景能不能只抹掉一部分？抹掉以后，它还是原来那个场景吗？
- 《部署笔记.md》删掉那一行后算新版本吗？旧版本里还留着密钥吗？
- 会话继续后再复制时，密钥会不会又被复制进来？
- “抹掉了什么”这件事本身记不记？如果记，这条记录会不会泄露被抹掉的内容？

## 十二、规模与时间

### 39. 一个场景带进来 2000 个网页

情形：一次会话里，agent 抓取了 2000 个产品页面，全部带进库，然后基于全部页面做出了一份《市场全景.md》。

经过：
1. 这张场景卡上有 2000 样带进来的东西和 1 样做出来的东西。
2. 一个月后，其中 3 个网页被重新抓取，内容变了。
3. 之后半年里，有 150 个场景各读了这 2000 个网页中的一两个。
4. 人在查看器里打开“市场全景”这条线索。

要回答的问题：
- 3 个网页变了，《市场全景.md》会不会被标成可能过期？
- 读过这 2000 个网页中任意一个的 150 个场景，是不是都和“市场全景”连成了一条线索？
- 这 2000 个网页是 2000 个条目，还是一个条目？

### 40. 五年、五万个条目，索引被删了

情形：一个用了五年的库，有 50,000 个条目、12,000 张场景卡。其中 30,000 个是第一年人用 Finder 从旧 Dropbox 一次拖进来的。

经过：
1. 那 30,000 个文件从进来那天起就来历不明，从来没人补过。
2. 场景卡里提到的 agent，有一半已经不存在了；对应的对话原文也早被清理了。
3. 人删掉了查看器建的索引。索引重建完之前，一个 agent 来查找东西；同时人在 Finder 里改了 200 个文件。
4. 人想把五年前的记录归档压缩，只保留最近两年的原样。

要回答的问题：
- 人能不能一次给那 30,000 个文件补上同一个来历？补上的来历算哪个场景？
- 索引重建完之前，查找能不能用？结果和重建后一样吗？重建以后，库还能不能发现那 200 个文件在这段时间里被改过？
- 记录只追加不改写。把五年前的记录归档压缩，算不算违反这一条？归档以后，老条目的来历还能不能查到？
