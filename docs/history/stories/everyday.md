# Pneuma Base 用户故事：顺利的日常与有野心的用法

只依据 CONTEXT.md 写成。这里写的是事情按用户希望的那样进行；失败、冲突和滥用由另一份故事覆盖。

CONTEXT.md 没定的地方，故事不替它定，只写出需要，标作“需要（CONTEXT 未定）”。

## 人物

- **林舟**：独立开发者，做小网站和小工具，常用 Claude Code 和 Codex。
- **陈蔚**：环境流行病学研究者，手上有大量 PDF 文献和数据集。
- **苏禾**：自由设计师，处理图片、品牌素材、可用性测试录像。
- **周屿**：非虚构作家，在写一本关于长江老船员的书，有很多采访录音。
- **马骏**：一家五人小公司的负责人。
- **王素琴**：退休教师，不懂技术，用它收藏菜谱和家里的老照片。侄女帮她装好了查看器。

## 一、一次会话里，agent 把资料和产出放进库

### 1. 选支付服务

- **谁、什么情境**：林舟在 `~/code/tiny-shop` 里用 Claude Code 给一个卖电子书的小网店选支付服务。他之前已经为 Claude Code 生成过这个库的技能和授权。
- **经过**：
  1. 林舟说：“比较一下 Stripe、Paddle 和 Lemon Squeezy，看哪个适合我这个小店。”
  2. Claude Code 读了三家的定价页和一篇独立开发者写的对比博客，一共 4 个网页。
  3. Claude Code 把这 4 个网页放进林舟的库，每个都带着原网址。
  4. Claude Code 写出一份对比笔记，结论是先用 Lemon Squeezy。
  5. Claude Code 写了一个 40 行的接入示例脚本。
  6. Claude Code 把对比笔记和示例脚本也放进库。
  7. 会话结束。林舟没有手动整理任何东西。
- **之后应当成立**：
  - 库里多了 6 个条目：4 个带进来的网页，2 个做出来的东西。
  - 这次会话有一张场景卡：要解决“给电子书小店选支付服务”，时间是那天，agent 是 Claude Code，读了 4 个网页，做了对比笔记和示例脚本。
  - 问对比笔记从哪来，得到这次场景，以及它粗略来自那 4 个网页。
  - 这 6 个条目自动关联成一组；从任何一个都能看到另外 5 个。

### 2. 文献综述的第一轮

- **谁、什么情境**：陈蔚在 `~/research/heat-mortality` 里用 Claude Code 为一篇综述找“高温与老年人死亡率”的文献。
- **经过**：
  1. 陈蔚让 Claude Code 找 2015 年以后的队列研究。
  2. Claude Code 从开放获取的期刊下载了 12 篇 PDF，放进她的研究库。
  3. Claude Code 每读一篇，就写一份一页的阅读笔记，放进库。
  4. Claude Code 做了一张汇总表（作者、地区、样本量、效应量），放进库。
  5. 陈蔚自己又拖进 2 篇她早就存着的 PDF，让 Claude Code 补进汇总表。
  6. Claude Code 读了这 2 篇，补写两份笔记，更新汇总表。
- **之后应当成立**：
  - 库里有 14 篇 PDF：12 篇标明是 Claude Code 在这次场景带进来的，2 篇标明是陈蔚本人在这次场景带进来的。
  - 每份阅读笔记能指回它读的那一篇 PDF。
  - 问汇总表来自什么，得到这 14 篇 PDF。
  - 场景卡上“读了哪些”列出 14 篇 PDF，“做了哪些”列出 14 份笔记和 1 张汇总表。

### 3. 咖啡馆品牌的情绪板

- **谁、什么情境**：苏禾在 `~/design/cafe-rebrand` 里用 Codex 为一家社区咖啡馆做品牌前期调研。
- **经过**：
  1. 苏禾说要“北欧、手写感、暖色”的参考。
  2. Codex 从几个设计网站找了 30 张参考图，放进库，每张带来源网址和作者名。
  3. 苏禾从自己电脑上拖进 5 张她在店里拍的照片。
  4. Codex 生成 3 套配色方案，每套是一张色卡图加一份色值说明。
  5. Codex 把参考图、店内照片和色卡拼成一张情绪板图片。
  6. Codex 把色卡、色值说明和情绪板都放进库。
- **之后应当成立**：
  - 问任何一张参考图，得到它的来源网址、作者，以及它是在“咖啡馆品牌前期调研”这次场景带进来的。
  - 苏禾的 5 张照片标明由人带进来；30 张参考图标明由 Codex 带进来。
  - 问情绪板来自什么，得到这 35 张图和 3 套配色。

### 4. 一段粘贴进来的文字

- **谁、什么情境**：周屿在 `~/writing/river-book` 里用 Claude Code 列第三章提纲。他手边有一本纸质回忆录，没有电子版。
- **经过**：
  1. 周屿把回忆录里约 300 字的一段话打出来，粘贴进对话，注明“摘自《江上四十年》第 87 页”。
  2. Claude Code 把这段话作为一个带进来的条目放进库，连同周屿给的出处。
  3. Claude Code 从网上找了两篇关于 1980 年代长江客轮的报道，放进库。
  4. Claude Code 写出第三章提纲，放进库。
  5. 周屿看了提纲，自己改了两处，让 Claude Code 把改过的放回库。
- **之后应当成立**：
  - 库里有这段粘贴的文字。它没有原文件，但带着周屿说的出处和它被粘贴进来的那次场景。
  - 问这段文字从哪来，得到“这次场景里由周屿粘贴，摘自《江上四十年》第 87 页”。
  - 问提纲来自什么，得到这段文字和两篇报道。
  - 库里的提纲是周屿改过的那一版。

## 二、换个目录、换个 agent，接着做

### 5. 第二天用 Codex 接上支付

- **谁、什么情境**：第二天，林舟新开了 `~/code/tiny-shop-v2` 重写网店，这次用 Codex。他之前也为 Codex 生成过同一个库的技能和授权。
- **经过**：
  1. 林舟只说：“把支付接上。”他没提昨天的事。
  2. Codex 从技能知道有这个库，读了库的说明。
  3. Codex 在库里按文字查“支付”，找到昨天的场景卡、对比笔记和示例脚本。
  4. Codex 告诉林舟：“库里有昨天 Claude Code 做的对比，结论是 Lemon Squeezy，我按这个接。”
  5. Codex 参考示例脚本写出正式的接入代码。
  6. Codex 把接入代码和一份接入说明放进库。
- **之后应当成立**：
  - 这次的场景卡写着：agent 是 Codex，读了昨天的对比笔记和示例脚本，做了接入代码和接入说明。
  - 昨天和今天的两次场景因为共用对比笔记连成一条线索；问这条线索，按时间得到这两次场景。
  - 问接入代码从哪来，能一路回到昨天的 4 个网页。

### 6. 一周后写基金申请

- **谁、什么情境**：一周后，陈蔚在 `~/grants/2027-proposal` 里用笔记本电脑上的 Codex 写基金申请的研究背景。
- **经过**：
  1. 陈蔚说：“写研究背景，突出高温对老年人影响的证据缺口。”
  2. Codex 读了库的说明，在库里按文字查“高温”“老年”，找到上周的汇总表和 14 份阅读笔记。
  3. Codex 读汇总表，发现缺少东亚地区的研究，把它写成证据缺口。
  4. Codex 引用时用的是库里那几篇 PDF。
  5. Codex 把研究背景草稿放进库。
- **之后应当成立**：
  - 问研究背景草稿的来历，得到这次场景和汇总表，再往上是 14 篇 PDF。
  - 上周的综述场景和这次的基金场景连成一条线索。
  - 陈蔚没有告诉 Codex 上周做过什么。

### 7. 两周后用 Claude Code 做菜单

- **谁、什么情境**：苏禾在 `~/design/cafe-menu` 里用 Claude Code 给同一家咖啡馆做菜单。上次的调研是用 Codex 做的。上周她还把自己在绘图软件里画好的 logo 拖进了库。
- **经过**：
  1. 苏禾说：“做一份 A4 菜单，和这家店的品牌一致。”
  2. Claude Code 读了库的说明，按文字查“咖啡馆”，找到情绪板、3 套配色和那个 logo。
  3. Claude Code 问苏禾用哪套配色；苏禾说第二套。
  4. Claude Code 做出菜单的 PDF 和可编辑的源文件。
  5. Claude Code 把这两样放进库。
- **之后应当成立**：
  - 菜单的场景卡上，“读了哪些”包括情绪板、第二套配色和 logo。
  - 问这家咖啡馆相关的所有东西，得到参考图、配色、logo、菜单，跨两个 agent、两个目录、三次场景。

## 三、多级加工

### 8. 从论文到会议幻灯片

- **谁、什么情境**：陈蔚的综述做了三个月，经过五次会话、两个 agent。
- **经过**：
  1. 第一级：14 篇 PDF（故事 2）。
  2. 第二级：14 份阅读笔记和汇总表（故事 2）。
  3. 第三级：一个月后，Claude Code 读了汇总表和其中 6 份笔记，写出“东亚证据缺口”专题综述，放进库。
  4. 第四级：Codex 读专题综述，写出论文的讨论部分，放进库。
  5. 第五级：会议前一周，Claude Code 读讨论部分和汇总表，做出 15 页会议幻灯片和讲稿，放进库。
  6. 每一次都留下了场景卡。
- **之后应当成立**：
  - 从幻灯片问来历，能一级一级回到那 14 篇 PDF；每一级都看得到是哪次场景、哪个 agent。
  - 从任意一篇 PDF 往下问，得到所有直接或间接用到它的东西，包括幻灯片。
  - 问专题综述来自什么，得到汇总表和那 6 份笔记，不是全部 14 份。
  - 这五次场景同属一条线索。

### 9. 从采访录音到章节终稿

- **谁、什么情境**：周屿为第五章采访了三位老船员。
- **经过**：
  1. 周屿把三段录音（共约 5 小时）带进库。
  2. Claude Code 在 `~/writing/river-book` 里把录音转成文字稿，三份文字稿放进库。
  3. 另一天，Codex 从文字稿里挑出 40 条引语，做成引语卡片放进库。
  4. 周屿自己删掉 12 张卡片，留下 28 张。
  5. Claude Code 用这 28 张卡片写出第五章初稿，放进库。
  6. 周屿和 Claude Code 来回改了三轮，第五章有了第 1、2、3 版。
- **之后应当成立**：
  - 第五章的每一版都能指回做出它的那次场景。
  - 问第五章来自什么，得到 28 张引语卡片，再往上是三份文字稿和三段录音。
  - 问某一段录音被用在了哪里，得到它的文字稿、来自它的引语卡片，以及第五章。
  - 被删掉的 12 张卡片不出现在第五章的来历里。

### 10. 从用户反馈到更新日志

- **谁、什么情境**：林舟的记账小工具上线三个月，攒了一份 600 行的用户反馈表格。
- **经过**：
  1. 林舟把反馈表格（xlsx）带进库。
  2. Codex 读表格，把反馈归成 9 类问题，写成问题清单放进库。
  3. 林舟挑了其中 3 类，让 Claude Code 写一份功能说明，放进库。
  4. Claude Code 按功能说明改代码。这个代码项目在库里是一个有版本的条目，由此多了一个新版本。
  5. Codex 根据新旧版本的差别和功能说明写出更新日志，放进库。
- **之后应当成立**：
  - 问更新日志从哪来，得到功能说明和代码的新版本；再往上是问题清单和反馈表格。
  - 问反馈表格被用在了哪里，得到这条链上的所有东西。
  - 这四次场景连成一条线索。

### 11. 原始数据换了，下游被标出来，再重做

- **谁、什么情境**：陈蔚的库里有一份 200 MB 的城市日气温表，以及基于它做出的三样东西：一张统计结果表、两张图。
- **经过**：
  1. 气象部门发布了修订版数据。陈蔚把库里的气温表换成修订版。
  2. 第二天她打开查看器，看到统计结果表和两张图被标成“可能过期”，原因是它们来自的气温表变了。
  3. 她在 `~/research/heat-mortality` 里对 Claude Code 说：“把可能过期的重做。”
  4. Claude Code 找到这三样，重跑分析，做出新的结果表和两张图，放进库。
  5. 陈蔚比较新旧结果，差别很小。
- **之后应当成立**：
  - 换数据之后、重做之前，问“可能过期的”，得到的正好是这三样。
  - 重做之后，新的结果表和图来自修订版气温表，不在“可能过期”里。
  - 库自己没有重做任何东西，重做是 Claude Code 做的。
  - 需要：陈蔚想要时还能看到修订前的结果，用来比较（CONTEXT 未定没有声明版本的条目被替换后旧内容怎么处理）。

## 四、问来历

### 12. “这个文件哪来的？”

- **谁、什么情境**：林舟在库里翻到一份限流笔记，完全不记得写过。
- **经过**：
  1. 林舟在查看器里点开这份笔记，看它的来历。
  2. 他看到：四个月前，Codex，在 `~/code/weather-bot` 里，要解决“调用天气 API 一直被限流”。
  3. 那次读了 3 个网页：API 文档的限流页和两篇讨论帖。
  4. 那次做了这份笔记和一个补丁。
  5. 他点开那次会话的引用。原始对话还在，他打开看了。
- **之后应当成立**：
  - 问这份笔记的来历，得到时间、agent、当时的工作目录、要解决什么、读了什么、同次还做了什么。
  - 林舟不需要记得当时在哪个目录、用的哪个 agent。

### 13. “我做这个的时候在干什么？”

- **谁、什么情境**：苏禾在查看器里看到一张没印象的手写体 logo 草图。
- **经过**：
  1. 苏禾打开这张草图所在的场景卡。
  2. 场景卡写着：去年 11 月，Claude Code，要解决“给朋友的独立书店想一个店招”。
  3. “读了哪些”：朋友发来的两张店面照片和一段语音转成的文字。
  4. “做了哪些”：5 张 logo 草图，这是其中一张。
  5. 当时她选了把整段对话复制一份进库。原会话早已清掉，但她还能读到当时的讨论。
- **之后应当成立**：
  - 从 5 张草图里的任何一张都能到这张场景卡。
  - 场景卡能回答“当时要解决什么”，不只是“当时做了什么”。
  - 复制进库的对话没有因为原会话被清掉而消失。

### 14. “那次会话还做了什么？”

- **谁、什么情境**：周屿写第七章时用了一张引语卡片，想看看同一次会话里还做了什么。
- **经过**：
  1. 周屿从这张卡片跳到它的场景。
  2. 他看到同一次场景里还做了 39 张卡片，以及一份“没用上的好故事”清单。
  3. 他早就忘了这份清单。里面有两条正好能用在第七章。
  4. 他对正在 `~/writing/river-book` 里工作的 Claude Code 说：“用这份清单里的第 3 条和第 8 条。”
  5. Claude Code 读了清单，把两个故事写进第七章。
- **之后应当成立**：
  - 问一个条目“同一次还做了什么”，得到那次场景做出来的全部条目。
  - 第七章这次的场景卡里，“读了哪些”包括那份清单。
  - 这份清单把旧场景和第七章的新场景连进同一条线索。

### 15. “这个月我在忙什么？”

- **谁、什么情境**：马骏月底要给合伙人写一份月报。
- **经过**：
  1. 马骏在 `~/work` 里让 Claude Code 帮他写本月月报。
  2. Claude Code 在库里查本月的全部场景，得到 47 张场景卡。
  3. 这些场景卡通过共用的条目连成 5 条线索，另有 6 张场景卡不属于任何线索。
  4. Claude Code 读每条线索里做出来的东西，给每条线索起了名字（新定价、客户 A 交付、招聘后端、竞品跟踪、官网改版），写出月报草稿。
  5. 马骏改了两句，Claude Code 把月报放进库。
- **之后应当成立**：
  - 问“这个月的场景”，按时间得到 47 张场景卡，并能看出它们分属哪条线索。
  - 马骏事先没有定义过任何一条线索。
  - 线索的名字和月报的内容是 Claude Code 写的；库只提供了场景、线索和条目。
  - 月报本身也是一个条目，它的来历指向这 5 条线索里的东西。

### 16. “我给你的数据，你都用在哪了？”

- **谁、什么情境**：一位合作者问陈蔚：“去年我给你的那份医院就诊数据，你都用在哪了？我要写进结题报告。”
- **经过**：
  1. 陈蔚在查看器里找到那份就诊数据的条目。
  2. 她查看哪些东西直接或间接来自它。
  3. 她得到：两份分析脚本、三张结果表、一篇已投稿论文的方法部分、一份会议海报。
  4. 她让 Codex 根据这份清单写一段给合作者的说明，附上每样东西的日期。
  5. Codex 写好说明，放进库，陈蔚把它发给合作者。
- **之后应当成立**：
  - 从一个带进来的条目往下问，得到所有下游条目，不管隔了几级、跨了几个 agent。
  - 每个下游条目都附带它的场景和日期。

## 七、有版本和可部署

### 25. 一百三十个小网站，四十二个在线

- **谁、什么情境**：过去一年，林舟让 Claude Code 和 Codex 做了 130 个小网站：活动页、小工具、作品集、给朋友的婚礼页。每个网站有 20 到 60 个文件。
- **经过**：
  1. 每个网站做出来时，agent 都把它作为一样东西放进库，声明为有版本、可部署。
  2. 年底，林舟在查看器里列出所有可部署的条目，一共 130 个，按最后修改时间排。
  3. 他逐个看场景卡，想起每个是为什么做的。
  4. 他装上 pneuma-space 部署插件，连到自己的 Cloudflare 账号。
  5. 他打开其中 42 个的部署开关，其余 88 个不动。
  6. 插件把这 42 个部署出去。
- **之后应当成立**：
  - 问“哪些在线”，得到这 42 个，每个带着线上地址。
  - 另外 88 个还在库里，版本和场景都完整，只是没有部署。
  - 每个网站在库里是一样东西，不是几十个零散文件。
  - 打开某个婚礼页的场景卡，能看到是哪天、哪个 agent、为谁做的。

### 26. 改一个在线的网站

- **谁、什么情境**：42 个在线网站里有一个读书会活动页，日期要改。
- **经过**：
  1. 林舟在随便一个目录里对 Codex 说：“读书会改到 12 月 14 号。”
  2. Codex 在库里按名字找到读书会活动页。

  4. 新版本被部署出去。
  5. 林舟打开线上地址，看到了新日期。
- **之后应当成立**：
  - 这个网站多了一个版本；上一版还在，看得出新版本是哪次场景改的。
  - 线上的是新版本。
  - 需要：林舟知道新版本放进库之后是自动部署，还是等他确认再部署（CONTEXT 未定部署插件什么时候动作）。

### 27. 下线，第二年再上线

- **谁、什么情境**：林舟有一个年度活动的网站，今年的活动结束了。
- **经过**：
  1. 活动结束后，林舟在查看器里关掉这个网站的部署开关。
  2. 网站下线。库里的条目、版本和场景都还在。

  4. Claude Code 在库里找到它，基于去年最后一版做出新版本。
  5. 林舟打开部署开关，网站上线。
- **之后应当成立**：
  - 下线期间，问“哪些在线”不包括它，问“所有网站”包括它。
  - 今年的版本来自去年的最后一版；两年的场景连成一条线索。

### 28. 有版本但不部署：书稿

- **谁、什么情境**：周屿的书稿每一章都是有版本的条目，不需要部署。
- **经过**：
  1. 第二章在半年里改了 7 版：4 版是 Claude Code 改的，2 版是 Codex 改的，1 版是周屿自己直接改的。
  2. 编辑问他：“第二章开头那个故事，为什么第 5 版删掉了？”
  3. 周屿在查看器里比较第 4 版和第 5 版。
  4. 他打开第 5 版的场景卡：要解决“把第二章压到 8000 字”，agent 是 Codex，读了编辑的批注 PDF。
  5. 他把这个理由转告编辑。
- **之后应当成立**：
  - 7 个版本都在，每一版都能回到它的场景。
  - 他自己直接改的那一版也有来历：要么改的时候就留下了，要么事后显示为来历不明、由他补上。
  - 书稿身上没有任何和部署有关的东西。

## 十、用查看器、只用命令行、什么都不用

### 35. 用查看器四处看看

- **谁、什么情境**：苏禾的设计库已经用了两个月，都是 agent 在读写。她第一次装查看器。

  1. 苏禾像用 brew 装别的应用一样装好查看器，选中 `~/Documents/设计库` 打开。
  2. 她浏览所有条目，按类型只看视频，再按场景找出和咖啡馆有关的几次。
  3. 她打开一条线索，看到咖啡馆项目从调研到菜单的几次场景按时间排开。
  4. 她看“来历不明”：有 3 张图是她直接拷进文件夹的。
  5. 她看“可能过期”：一个也没有。
  6. 她关掉查看器，把它卸载了。第二天 Claude Code 照常用这个库。
- **之后应当成立**：
  - 查看器里看到的和库文件夹里的记录一致。
  - 卸载查看器之后，库完好，没有丢任何记录。

### 36. 只用命令行

- **谁、什么情境**：林舟在一台远程 Linux 服务器上跑一个房租数据抓取项目，那里没有图形界面。
- **经过**：
  1. 林舟把个人库同步到这台服务器。
  2. 在服务器的 `~/scrapers/rent-prices` 里，Claude Code 用命令行把抓到的 3 个城市的房租数据和一份清洗说明放进库。
  3. 林舟自己用命令行按文字查“房租”，看到这几个条目和它们的场景。
  4. 他用命令行列出“来历不明”和“可能过期”的条目，都是 0 个。
  5. 他用命令行为服务器上的 Codex 生成一份技能和授权，让它明天接着做。
  6. 回到自己的 Mac 上，他在查看器里打开同步回来的个人库。
- **之后应当成立**：
  - 不装查看器，人和 agent 都能完成放进、查找、看来历、列出来历不明和可能过期、生成授权这些事。
  - Mac 上的查看器里能看到服务器上做的这些条目和场景。

### 37. 一个只会读写文件的 agent

- **谁、什么情境**：马骏公司有个跑在沙盒里的内部 agent，它只能读写一个挂进来的文件夹，没有 Pneuma Base 的命令行，也没有查看器。马骏把公司库挂给了它。
- **经过**：
  1. 马骏让它“整理一下竞品 X 本周发布的新功能”，并贴给它三段发布说明。
  2. agent 先读到库根目录的说明，知道这里是一个库，以及放东西、留场景卡的规矩。
  3. agent 写了一份功能对比。
  4. agent 按说明里的规矩，把三段发布说明和功能对比放进库，并写下这次的场景卡。
  5. 当天下午马骏在自己电脑上用查看器打开这个库。
- **之后应当成立**：
  - 查看器里这四样东西都有来历，属于这个 agent 的那次场景，不在“来历不明”里。
  - 场景卡写着 agent 是那个内部 agent，要解决的是“竞品 X 本周的新功能”。
  - 整个过程里，那个 agent 那边没有装任何 Pneuma Base 的软件。
