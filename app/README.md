# Pneuma Base 的 Mac 外壳

一个 Swift 写的原生外壳，里面是现有的管理界面（`pneuma-base view` 起的本机网页）。它把主人要走的那条路接起来：选一个文件夹，把资料放进去，一个一个接上 agent，开始干活；其余时候待在菜单栏里。

应用自带一个 Node 和命令行（连同管理界面、五个自带的插件、本机文件夹的存储提供者和契约测试的程序），下载下来什么都不用另装。外壳不持有库的状态。它只记得这台机器认识哪些库、当前是哪个、监看上次听到哪里、它自己的设置；对库做的每一件事都经它自带的命令行做，监看就是存储自己的订阅。没有开发者证书签名，别人下载后第一次打开要多走几步，见文末「发给别人」。

## 构建和打开

```sh
app/build.sh --node <一个独立的 node>      # 或设 PNEUMA_BASE_NODE；都不给就用 PATH 上的 node
open "app/dist/Pneuma Base.app"
app/build.sh --node <…> --dist             # 另打一个 zip，给别人下载
```

`build.sh` 一条命令做完：`pnpm build`（没装依赖就先 `pnpm install`），`swift build -c release`，再用 `scripts/pack-dist.mjs` 打出命令行的包文件、解开放进应用，拼成 `app/dist/Pneuma Base.app`，最后用 `codesign --sign -` 做本机签名。双击 Finder 里的 `Pneuma Base.app` 也一样。

应用里有什么：

| 位置 | 是什么 | 大小 |
| --- | --- | --- |
| `Contents/MacOS/Pneuma Base` | 外壳 | 0.7 MB |
| `Contents/MacOS/node` | 构建时找到的那个 Node，原样拷进来；有签名的保留它自己的签名，没有的给它一个本机签名 | 117 MB |
| `Contents/Resources/cli/` | 命令行的包：`dist/bin.js`，`node_modules/` 里的内核、sdk、管理界面和五个自带插件，`PLUGINS.md`、`LICENSE`；内核旁边的 `bin/` 里是 Apple 芯片的本机文件夹提供者 `pneuma-base-core`（4.7 MB）、契约测试的程序 `pneuma-base-contract`（2.2 MB）和写着 `darwin-arm64` 的 `platform` | 9.8 MB |
| `Contents/Resources/` 其余 | 图标、`shell.js`、`parent-watch.mjs` | 0.2 MB |

合起来 128 MB（`du -sh`，2026-11-27 的构建），zip 是 43 MB。Node 要合两条：不低于命令行的 Node 下限（22.18，写在 `packages/cli/src/node-floor.ts`，`build.sh` 用它自己核），只依赖 macOS 自己的库（`otool -L` 里只有 `/usr/lib/` 和 `/System/Library/`）。nodejs.org 的构建合；Homebrew 的不合（它的 `node` 只有 130 KB，其余在 `libnode` 和几十个 Homebrew 的动态库里），`build.sh` 拒绝它，并给出同版本的 nodejs.org 下载地址。构建出来的应用只是这台机器的架构（`build.sh` 印出的 `built …` 那一行里有 `lipo -archs` 的结果）；产品只给 Apple 芯片的 Mac，存储的程序不是 `darwin-arm64` 的，`build.sh` 拒绝打包。

能变小的地方（量过的标「量过」）：

- `strip -x` 去掉 Node 的本地符号：122.6 MB 变成 98.4 MB（量过），去掉之后照样能跑命令行（量过），zip 只小 3 到 4 MB（量过）。代价是 Node 自己的签名没了（要重签），崩溃时的调用栈没有名字。没有做。
- 自己编一个 Node：只带少量 ICU（`--with-intl=small-icu`）、不带调试器（`--without-inspector`）。估计能再小 25 到 30 MB（推测，没有编过）；代价是要维护一条 Node 的构建，`Intl` 只认英文。
- 同时支持 Intel 要把两个 Node 合成一个通用的，Node 那一份翻一倍。

用 SwiftPM 而不是 Xcode 工程：没有 `.xcodeproj` 这种难审阅的文件，`swift build` 在命令行上每次得到一样的结果，不需要打开 Xcode 点任何东西。代价是 `.app` 由脚本拼装，资源文件不走 SwiftPM 的资源机制。

第一次打开、还没有库时，只出一个小窗口：两句话，问库放在哪。它按 `storage list` 列出这台机器的存储提供者和官方的、没装的；只有本机文件夹一个时，就是「选一个文件夹…」，下面一个「安装别的存储…」。有几个时多一个弹出菜单：选一个答文件夹的提供者再选文件夹（`init <文件夹> --provider <名字>`），选官方没装的先装上它；答的地址不是文件夹的，按钮上写着，不能在这里建。「安装别的存储…」问一个 GitHub 仓库，跑 `storage install`；命令行答的那句信任的话（存储提供者以你的身份运行、看得到库里的全部内容，仓库、版本、校验和）原样放进一个对话框，点「安装」就带着那个校验和再跑一次。选的文件夹不是库就建成库，然后主窗口打开在它的首页上，首页最上面是「开始」。之后应用待在菜单栏里（一个带平底的环）：点它是一个小面板，右键是库的菜单。也可以启动时直接给一个库：

```sh
open "app/dist/Pneuma Base.app" --args --library ~/某个库
```

### 用的是哪个家目录

应用给它起的每个命令行进程设 `PNEUMA_BASE_HOME`，缺省是真的 `~/.pneuma-base`，和从包里装的命令行用的是同一个。应用自己的小配置（认识哪些库、当前是哪个、这台机器的设置）和日志在它的 `app/` 里：`~/.pneuma-base/app/libraries.json`、`~/.pneuma-base/app/app.log`。

启动时给 `--home` 换一个，或者设环境变量 `PNEUMA_BASE_HOME`：

```sh
open "app/dist/Pneuma Base.app" --args --home /tmp/试一试
```

`verify.sh` 和 `measure.sh` 总是用临时的家目录。

### 本机的命令

应用每次启动都跑一次自带命令行的 `launcher install`：让 `~/.pneuma-base/bin/pneuma-base` 指向应用里的 Node 和命令行。它是一个小脚本：

```sh
#!/bin/sh
# 这台机器上的 pneuma-base。接上的 agent 按这个路径运行它，路径不变，内容由提供命令行的一方保持最新：
# Pneuma Base 应用每次启动时，或 pneuma-base launcher install。
PNEUMA_BASE_HOME='/Users/<你>/.pneuma-base'
export PNEUMA_BASE_HOME
exec '/Applications/Pneuma Base.app/Contents/MacOS/node' '/Applications/Pneuma Base.app/Contents/Resources/cli/dist/bin.js' "$@"
```

接上 agent 时写进去的（技能里的命令行、MCP 条目的 `command`）都按绝对路径写这个脚本，所以 agent 的 PATH 上什么都不用有，也找得到授权所在的家目录。应用挪了位置或换了新版，下次启动时脚本跟着改，接上的 agent 不用重接。内容没变就不写。不要管理员权限，不改 PATH。

macOS 把从解压出来的地方直接打开的下载应用放在一个临时的位置运行（App Translocation），退出后那个位置就没了，脚本指向那里就会断。应用看到自己在这样的位置上，会先说：把它拖进「应用程序」文件夹再从那里打开，可以退出，也可以先这样用。

### 设置

「Pneuma Base › 设置…」（⌘,）或菜单栏图标的右键菜单打开设置窗口，都是这台机器的设置：

- **直接放进来的文件算主人的**：和菜单里那一项是同一个，缺省开着。
- **在终端里用 pneuma-base**：缺省关着。打开时，在你选的一个文件夹里放一个叫 `pneuma-base` 的符号链接，指向本机的命令；可选的是你的 PATH 上你能写的文件夹（问你的登录 shell 要 PATH，三秒没答复就用应用自己的）。那里已经有一个不是这里放的 `pneuma-base`，不动它，说出来。本机的命令所在的文件夹已经在 PATH 上时，只说这一句。一个能写的都没有时，给出要加进 shell 配置文件（zsh 是 `~/.zshrc`，bash 是 `~/.bash_profile`）的那一行，比如 `export PATH="/Users/<你>/.pneuma-base/bin:$PATH"`，只显示、可以拷贝，不写。关掉时，链接还指向本机的命令才拿走。
- **登录时打开**：缺省关着，用系统的 `SMAppService.mainApp`。这台机器的规矩不许真的装登录项，所以注册这一步没有试过；没签名的应用上系统答应不答应，没有验证。系统要你在「系统设置 › 通用 › 登录项」里允许时，设置里会说。
- 最下面写着本机的命令在哪。

## 五分钟试一试

1. 打开应用。没有库时出来一个小窗口，两句话和「选一个文件夹…」。菜单栏出现带平底的环形图标。
2. 点「选一个文件夹…」，新建一个空文件夹并选它。小窗口关掉，主窗口打开在首页，最上面是「开始」：0 / 3。
3. 第一步「接上你的 agent」列出这台机器上找到的产品，每个一行。点一个的「接上」，不出表单，一下就接上了，这一步折成一行「已接上 …」。装进去的技能和 MCP 条目都写本机的命令的完整路径，agent 那边不用另装什么。这一步里还有一句可以复制的话：「读一下 http://127.0.0.1:7638/guide，接上我的 Pneuma Base 库。」说给任何一个 agent，它读这台机器给它的产品写的说明，请你允许；首页「等你决定」里出现「<产品> 想接入这个库：允许吗？」，配对码和 agent 给你看的一样就点「允许」，它就以自己的名字接上了。7638 被占时端口会不同，照页上写的说；Agent 页上也有这句话。
4. 第二步「放进第一样东西」是一块虚线的区域。从 Finder 拖一个文件到窗口的任何地方，窗口出现「松开，放进库的 inbox/，记成你带进来的」，松开后右下角一条提示，这一步折成「库的根目录里有 1 样东西」。点区域里的「选择…」，可以选文件和文件夹，效果一样。窗口开在库页的某个文件夹上时，拖进来的放进那个文件夹。
5. 第三步是一句可以复制的话。在接上的 agent 里说它；agent 在库里做过一件事，「开始」就没了。
6. 点菜单栏的环形图标：一个小面板，顶上是库名，然后是等你决定的前三件（在这里就能回答）和自上次以来的最新几行，底下「打开窗口」「退出」。有事等你时，图标左上角有一个点。右键图标（或按住 Control 点它）是库的菜单：换库、新建或打开一个库、打开窗口、「直接放进来的文件算主人的」、设置、退出。
7. 在 Finder 里把一个文件复制进库的文件夹。库里安静 3 秒后它被登记为主人带进来的（自动登记）；窗口开着时右下角一条提示，没开时是一条通知（这台机器上发不出去，见下）。用文本编辑器直接改一个已登记的文件，同样记成看到的改动。在「Pneuma Base」菜单或右键菜单里关掉「直接放进来的文件算主人的」，就不再自动登记。
8. 在系统设置里切换浅色和深色，窗口和面板立刻跟着变。按 ⌘W 关掉窗口，Dock 图标消失；点面板的「打开窗口」，它回到原来的位置和大小。
9. 在页面上试 ⌘F（右上角出现搜索框）、⌘C、⌘V、⌘R（重新载入，在「显示」菜单里）、⌘[ 和 ⌘]（后退、前进）。
10. 用 ⌘Q 或面板的「退出」退出，在终端里 `ps ax | grep "bin.js view"`，看不到它起的服务。

## 什么是真的，什么是假的

真的：第一次的小窗口，菜单栏图标、它的面板和右键菜单，窗口和它的原生外框、主菜单和快捷键、拖放和选文件、存储的订阅、子进程的启动、重启和退出。拖放、选文件和监看都经命令行写库（`put … --brought --by owner`，监看另加 `--observed`；`say revised --observed`），应用自己从不写库里的记录。

- 面板是网页的一种排法（`?shell=mac&panel=tray`），装在一块挂在菜单栏图标下面的无边框面板里，像系统自己的菜单栏小程序：没有箭头，圆角，一道细边，有阴影，网页画自己的底。头上是库名（点了在窗口里打开首页）、有事等着时的个数、打开窗口的图标和「···」：「···」是应用自己的菜单（外观、库、设置…、退出）。点别处、按 Esc、再点图标都关上它。它的网页视图第一次打开面板时才造，之后留着，所以再打开是立刻的；面板不显示时网页不问服务。面板告诉应用它的内容多高，应用照着定面板的高，最多 600 点，也不超过菜单栏下面的空间，再长网页在里面滚。
- 图标上的点：应用数首页上等主人决定的事（`show home --json` 里所有 `asks` 块的件数）。应用每 2 秒问一次自己起的服务的摘要（`/api/rev`，页面重取用的同一个：各插件的事实到哪了、展开的目录的令牌和它们这一层里的最新变化、这台机器的配对），窗口开不开都问；摘要变了就数一次，放完东西数一次，另外每分钟一次；面板开着时用面板说的数。
- 「直接放进来的文件算主人的」是这台机器的设置，缺省开着，记在应用的小配置里（`ownerFiles`），不在库里。
- 「外观」也是这台机器的设置：跟随系统（缺省）、浅色、深色，记在应用的小配置里（`appearance`，没写就是跟随系统）。面板的「···」、菜单栏图标的右键菜单、设置窗口、配置页的「这台机器」都能选。它设的是应用的外观（`NSApp.appearance`），窗口、面板、系统的表单和菜单跟着变；网页视图的 `prefers-color-scheme` 也跟着它，网页据此换 `data-scheme`，所以两个网页同时变，不用重启。
- 拖进来、选进来的东西放进窗口正在看的文件夹（地址里的 `view.dir`，库页和文件页都用它），没有就放进库根的 `inbox/`；同名时按 Finder 的习惯加「 2」「 3」。出处是 macOS 记下的下载地址，没有就是它原来所在文件夹的名字。

假的或凑合的：

- 签名是本机签名（ad hoc），见文末「发给别人」。
- 通知中心：代码按正式的做法写了（`UNUserNotificationCenter`，点通知打开窗口），但这台机器上系统拒绝了这个本机签名的应用（`Notifications are not allowed for this application`），一条通知也发不出去。窗口开着时，同样的话改成网页右下角的一条提示，这一条是能用的。用开发者证书签名后通知大概能用，没有验证。
- 一次只有一个库在用：一个窗口、一个服务子进程、一个监看。换库时先停掉旧的。
- 应用里留着只给测量和检查用的钩子，只在启动时带 `--hooks <名字>` 才听，听的是分布式通知 `dev.pneumabase.hooks.<名字>`，检查脚本只驱动它自己起的那一份。能做的：打开、关闭、退出、报进程号（应用、服务、网页进程、存储提供者）、把窗口挪到屏幕角落、切换深浅色、问一个点击归谁、查找、像选了一个文件夹那样打开库、按拖到菜单栏图标或窗口上的同一段代码放进一个文件、设页面地址的片段、点图标、把窗口或面板的文字写到文件、把第一次的小窗口提供的选择写成字、给窗口、面板、第一次的小窗口、设置窗口拍一张图、打开设置、像那个开关一样放上和拿走 PATH 上的链接、把设置写成字、在窗口的网页里跑一段 JavaScript 并记下结果（检查用它替网页给外壳发消息）、选右键菜单里的一项（带钩子时菜单不弹出来，只记下它的各项）、让某个位置像只留了占位的文件那样回答、开关「直接放进来的文件算主人的」；选外观并把它写成字（选的、记下的、应用、窗口、面板、两个网页各是深是浅）、弹面板的「···」（带钩子时不弹出来，只记下它的各项，像右键菜单那样选一项）、假装菜单栏下只有多高的空间、把面板能不能看全写成字（面板多高、滚不滚、最后一行在不在看得见的地方、最高的一行多高、回答以外有几个带字的按钮）；只拍自己的窗口（连着它的表单）或面板（`CGWindowListCreateImageFromArray` 只取自己的窗口，不要录屏的权限）、改窗口大小；按窗口上那张系统表单的第几个按钮。带钩子时，外壳伸到应用外面的事（打开、在访达中显示、写剪贴板、开终端）只记一行 `opener: …`，什么都不真的打开。见 `App.swift` 末尾。

网页这边有两处开关。应用载入网页时带 `?shell=mac`，网页据此在 `<html>` 上标 `data-shell`，改用系统字体，给左边栏顶部留出红黄绿按钮的位置（边栏收成一列图标时，收起的按钮挪到三个按钮下面空出来的那一行，不被它们盖住），把「用 pneuma-base view 启动」这类只对浏览器有意义的提示换掉，并让外框部分不能选中文字、不出现文字光标、整页不回弹。窗口成为或不再是前台窗口时，应用在网页里发一个 `pneuma-shell` 事件，带 `{ window: 'active' }` 或 `{ window: 'inactive' }`，网页内容就绪时也发一次；网页据此在 `<html>` 上标 `data-window`，窗口在后面时把边栏的选中项、图标、标签和标题调淡，像系统的窗口那样。可以拖动窗口的区域由网页用 `data-drag` 标出，应用注入的 `Resources/shell.js` 把这些区域的位置报给原生的 `WKWebView` 子类，鼠标在这里按下就由系统拖窗口。浏览器里打开时没有 `shell=mac`，网页不做这些改动。面板再带 `panel=tray`。网页和外壳之间的每一条消息写在 `ARCHITECTURE.md`「壳里的网页」里。

## 数字

`app/measure.sh <库> [轮数]` 在一个库上量几轮，缺省三轮，每轮量这几样：

- 启动：从脚本调 `open` 到应用日志里「status item shown」的时刻，另报从内核起进程算起的时间。
- 打开窗口：从 `openWindow()` 被调用，到窗口显示之后网页的第二个动画帧；第一次，和关掉再开的第二次。
- 空闲的内存和 CPU：窗口开着（窗口挪到屏幕角落）和关窗口 75 秒后，各进程的 `footprint`，和 60 秒里 `ps` 的累计 CPU 时间之差。量的进程是应用、服务（Node）、网页进程和 WebKit 的 GPU、网络进程；两个存储提供者进程（监看起的、服务起的）不在其中。60 秒里退出了的进程写「exited」，不把它一生用过的 CPU 算进来。

它用临时的 `PNEUMA_BASE_HOME`，经钩子驱动应用。这份代码上量出的时间、内存和 CPU 还没有记下；记下的只有上面「应用里有什么」里的大小。

## 核对过的和要人来看的

`app/verify.sh` 沿新主人走的那条路核对构建好的应用，用临时的 `HOME` 和临时的 `PNEUMA_BASE_HOME`（`open -n --env`），不读不写这台机器上真的 agent 配置和库。它用的命令行就是应用自带的 Node 和命令行，PATH 上只有系统工具。它起的那一份应用带自己的钩子名，按钩子名找进程、停进程，从不按应用的名字退出别的那一份。逐条核对：

- 第一次启动写好本机的命令，指向应用里的 Node 和命令行、导出这个家目录；服务进程跑的也是应用里的 Node 和命令行。
- 没有库时第一次打开，出来小窗口；像选了一个文件夹那样（钩子，走同一段代码），文件夹被建成库，主窗口打开，服务是应用的子进程，首页最上面是「开始」，0 / 3。
- 经拖到窗口上的同一段代码放进一个文件：在 `inbox/`，「带进来的，主人给的 · 主人」，出处是文件夹名；第二步折成「库的根目录里有 1 样东西」。窗口开在库页的 `docs/` 上时，拖进来的放进 `docs/`；拖到菜单栏图标上的进 `inbox/`。
- 第一次的小窗口问库放在哪：只有本机文件夹一个提供者，弹出菜单不出来，按钮是「选一个文件夹…」，旁边是「安装别的存储…」。应用里带着 `darwin-arm64` 的本机文件夹提供者和契约测试的程序，`storage list` 说本机文件夹从应用里运行。
- 监看是提供者的订阅：建库之后，应用的子进程里有 `<应用里的 bin>/pneuma-base-core serve --root <库>`。
- 直接写进库里的文件经订阅报来，被监看登记成「带进来的，主人给的（自动登记）」；用 `xattr` 写了下载地址的，出处是那个地址；直接改一个已登记的文件，记成「直接改的，自动登记」。
- 直接写进去一个放着三个文件的小文件夹，登记成一样东西；写进去一个带 `package.json`、八万个文件的项目目录，首页出现「proj/ 没登记：…」，监看的探查说它超出预算、顶上有 `package.json`，`inspect proj` 说它是没登记的目录，里面一个文件都没登记。
- 假的 `~/.claude`（在临时 `HOME` 里）让第一步列出 Claude Code；`agent connect claude-code` 把技能写进临时 `HOME`，第一步折成「已接上 Claude Code」。
- 技能里的三行命令（start、put、find）都以本机的命令的完整路径开头；把占位换掉，用 `env -i`、PATH 只有 `/usr/bin:/bin`、不设 `PNEUMA_BASE_HOME`，像 Claude Code 那样经 `sh -c` 原样跑，三行都成；放进去的那样东西是「做出来的 · claude-code」，场景是 start 说的那句。
- 假的 Claude Desktop 接上之后，它的 MCP 条目是 `<本机的命令> @claude-desktop mcp`，没有 `env`；用 `env -i` 照条目起它，`initialize`、`tools/list` 得到全部工具，经它 `put` 的东西是 Claude Desktop 的。
- agent 放的 5 个文件都还是 agent 的，监看一个也没登记。
- agent 说一个站点可以部署之后，图标上出现点；首页的「开始」没了（有 agent 做过事了）；点图标打开面板，面板里有库名、那件要决定的事和「打开窗口」。

## 监看和 agent 自己的放入

监看是存储自己的订阅，应用没有自己的事件流。换到一个库时，应用用 `storage list --library <库> --json` 问它用哪个提供者、程序在哪，起这个程序的常驻模式（`serve --root <库>`，应用的子进程），发一条 `subscribe`，带上次听到的游标（记在 `libraries.json` 的 `cursors` 里），所以应用没开着时放进来的东西，下次打开也听得到。存储报来的是位置，不含噪音和记录区；同一个进程里还能问只读的操作，监看用它的 `probe`。提供者意外退出时，监看等一会儿再起它（从 0.25 秒起每次加倍，最多 10 秒），从记下的游标接着订阅。退出时关掉它的输入，提供者取消订阅后自己退出（两秒还没退就停掉它）；应用被杀，管道断了，它一样退出。

agent 放东西时，内核先在存储里占住要改的位置，把东西放上去，等插件都记下才放开；记账插件的状况页不报被占着的位置，也不报对账期间有了记录的位置。所以「这个文件有没有人登记」只问记账插件，监看自己不另做判断。

监看的规则：

1. 只看上次看过之后订阅报来过的位置（`PNEUMA-BASE.md` 和归档区不算）。
2. 等库安静 3 秒，这是为了不把主人还在复制的文件拿走一半。
3. 读一次 `show ledger.standing --json`（不用 `check`：主人的 `check` 会记一条「看过了」，把首页的「自上次以来」清掉）。
4. 「没人登记过的」里报来过的文件，`put <路径> --brought --by owner --observed --note 自动登记`，有下载地址的加 `--source`；「被直接改过的」里的，`say revised <路径> --observed`。
5. 「没登记的目录」里报来过的（它自己或里面的东西），先在订阅的那个进程上 `probe`，预算 500 项：没超出、顶上没有项目标记（`package.json`、`.git` 这些）的，同样 `put` 登记成一样东西；别的不动，它就是记账插件在首页上问主人的那一句（「proj/ 没登记：至少 … 个文件，像一个项目（package.json）。」，带三个答案）。一个八万个文件的项目目录因此是一句问话，不是八万次登记。
6. 如果在这次看和这次放之间别人登记了它，`put` 答「已在册」，只算加了一条备注。

agent 违反说明、在库里直接写文件又过了几秒才登记的，监看会先把它登记成主人带进来的（看到的）；agent 之后的 `put --made` 是说的，盖过看到的，来历改成 agent 做出来的，看到的那条留在「先前」里。

实验 `app/experiments/put-race.mjs` 查监看会不会把 agent 正在放的东西当成主人的，可以重跑，有三种模式：

- `window`：agent 一个接一个地放文件，量文件出现到第一条新事实之间的空档。
- `marks`：不开应用，agent 一个接一个地放文件，两个读者背靠背地读状况页，和监看读的一样；放着的文件不该出现在「没人登记过的」里。同时在库里直接写的几个文件（没有放）是对照，读者要把它们列出来。
- `app`：开着应用，agent 按说明从库外放文件（有小的，有 50 MB 的），每次前停一个监看等安静那么久，让它的看落在放上；再让 agent 在库里直接写文件、隔几秒才登记。最后读每个文件的来历，和应用日志里监看有几次看和放重叠。

这份代码上跑出的结果还没有记下；它要核对的「agent 放的都还是 agent 的」，`verify.sh` 每次都核（见上面）。

## 哪里还不像原生

已经是原生的：窗口和外框（红黄绿按钮、全屏、拼贴、调度中心、位置大小记住）、菜单栏图标和菜单、主菜单和快捷键、⌘F 的搜索框（原生工具栏搜索项，查找交给 `WKWebView.find`）、滚动（WebKit 用系统的惯性滚动和浮动滚动条）、文字渲染（CoreText）、选中文字时的右键菜单（系统的拷贝、查询、翻译）。下面这些还看得出是网页，每一条写明在这个方案里能不能补上。

| 哪里 | 现在 | 能不能补 |
| --- | --- | --- |
| 字体 | 已补：外壳模式下 `--font-sans` 是系统字体（SF Pro 和苹方），表格量列宽也按它量 | — |
| 强调色 | 网页没有自己的强调色：主要按钮近黑，蓝色只给键盘焦点和「进行中」；不跟系统设置里的强调色和高亮色 | 能。外壳模式下把 `--focus` 换成 WebKit 认的 `AccentColor` |
| 左边栏的材质 | 网页画的平的灰色；系统的边栏是半透明的，macOS 26 上还是浮起来的玻璃 | 试过把系统的玻璃垫在网页的边栏下面（2026-11-28）：只有一个网页，玻璃只能透窗口后面的桌面，在真的桌面前透出后面窗口的字和图，成了一块块灰影，主人不要，拿掉了。像系统那样浮起、透窗口自己内容的边栏要原生视图 |
| 窗口失去焦点时 | 已补：外壳把窗口的前后状态告诉网页（上面的 `pneuma-shell` 事件），边栏的选中项和图标变淡 | — |
| 控件 | 分段选择、按钮、焦点框、悬停高亮都是网页画的；系统的边栏没有悬停高亮，焦点框也不是这个样子 | 大部分能靠外壳模式的 CSS 拉近，做不到一模一样。要一模一样就得用原生控件 |
| 列表的键盘操作 | 表格里上下键、Home、End 在行之间走，回车打开，只有一行在 Tab 的顺序里；边栏的页也用上下键走。没有按字母跳转和空格预览 | 能，在网页里写；空格预览用外壳调系统的快速查看（`QLPreviewPanel`） |
| 拖出去 | 不能把一行拖到 Finder 或别的应用里 | 能。网页告诉外壳从哪一行开始拖，外壳用 `NSDraggingSession` 拖出真的文件 |
| 行上的右键菜单 | 没有（空白处的浏览器菜单去掉了）；系统应用在行上给「在 Finder 中显示」「归档」 | 能。网页把要显示的菜单项交给外壳，外壳弹 `NSMenu` |
| 打开窗口的速度 | 关窗口时网页进程随窗口销毁，再打开要重新起网页进程、取页面和数据；内容就绪之前窗口不显示（最多等 1 秒）。原生窗口几乎是立刻的 | 部分能。关窗口时留着网页不销毁，第二次打开就是立刻的，代价是一个网页进程的内存和每 2 秒一次的查询 |
| 刷新 | 网页每 2 秒问一次库有没有变 | 能。外壳已经订阅了存储的变化，可以把变化直接推给网页，不用轮询 |
| 内存 | 窗口开着时有七个进程：应用、服务的 Node、两个存储提供者（监看起的和服务起的）、网页进程、WebKit 的 GPU 进程和网络进程；同样功能的原生应用只有一个 | 不能根本改变。Node 和 WebKit 的几个进程是这个方案的底数 |
| 通知 | 本机签名的应用被系统拒绝，见上面 | 和方案无关，正式签名的问题 |

我的判断：内容区（表格、详情面板、对话框）在这个方案里能做到一般人分不出来；做不到「分不出来」的是外框里的那几样：浮起的玻璃边栏、原生控件的手感、列表的键盘和拖放习惯。它们单独看都能用网页模仿个大概，但每一样都是在网页里重写一遍 AppKit 已经有的行为，越往细处越贵，也永远差一点。所以 1.0 建议改成混合的：边栏和工具栏用原生视图（`NSSplitViewController` 的边栏、`NSOutlineView`、`NSToolbar`），内容区留网页；外壳和网页之间就是现在的这几条消息（拖动区域、画好了、拖放、查找），再加上导航和选中。

## 发给别人

`app/build.sh --node <…> --dist` 在 `app/dist/` 里打一个 zip（`ditto -c -k --keepParent`），43 MB。应用只有本机签名（ad hoc），没有开发者证书，没有经过 Apple 公证。下面按 Apple 的说明写，没有在别的机器上从网上下载点过一遍。

别人下载之后，在现在的 macOS（15 和 26）上第一次打开要做的：

1. 双击 zip 解开，把「Pneuma Base」拖进「应用程序」文件夹。不拖就打开，macOS 让它在一个临时的位置运行，应用会先提醒（见上面「本机的命令」）。
2. 双击打开。系统说 Apple 无法验证它是否含有恶意软件，只给「完成」和「移到废纸篓」。点「完成」。按住 Control 点「打开」的老办法在 macOS 15 上已经没有了。
3. 打开「系统设置 › 隐私与安全性」，往下翻，在说 Pneuma Base 被阻止的那一行点「仍要打开」，输入密码或用触控 ID。
4. 再双击一次，在弹出的对话框里点「仍要打开」。之后每次都直接打开。

另外：通知发不出去（系统拒绝本机签名的应用，见上面）；登录时打开不知道系统答不答应；只能在和构建的机器同一种芯片的 Mac 上运行，现在是 Apple 芯片。

用开发者证书签名并公证之后会变的：第一次打开只问一句「这是从互联网下载的，确定要打开吗」，不用去系统设置；通知和登录项按正常的应用对待。不会变的：没拖进「应用程序」就打开时照样在临时位置运行，那句提醒照样有用。要做的是：加入 Apple Developer Program 拿一张「Developer ID Application」证书；`build.sh` 里的两次 `codesign` 改用这张证书、加 `--options runtime` 和时间戳（Node 在加固的运行时里要 `com.apple.security.cs.allow-jit` 这个权限，nodejs.org 的 Node 自己的签名已经带着）；再用 `xcrun notarytool submit` 送去公证，`xcrun stapler staple` 把结果钉在应用上，最后打 zip。
