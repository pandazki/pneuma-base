# Pneuma Base 的 Mac 外壳

一个 Swift 写的原生外壳，里面是管理界面（`pneuma-base view` 起的本机网页）：窗口、菜单栏的面板、拖放、监看、这台机器的设置。应用自带 Node 和命令行，下载下来什么都不用另装；只给 Apple 芯片的 Mac，macOS 14 起。

外壳不持有资料库的状态。对资料库做的每一件事都经自带的命令行：拖放和选进来的文件是 `put … --imported --by owner`，监看另加 `--observed`，直接的改动是 `say revised --observed`；应用自己从不写资料库里的记录，看资料库也只经存储的只读操作。一次只有一个资料库在用：一个窗口、一个服务子进程、一个监看，换资料库时先停掉旧的。外壳能做什么、不能做什么和为什么，在 [`ARCHITECTURE.md` 第 10 节「壳」](../ARCHITECTURE.md#10-壳)；网页和外壳之间的每一条消息在 [「壳里的网页」](../ARCHITECTURE.md#壳里的网页)。

| 位置 | 是什么 |
| --- | --- |
| `Sources/PneumaBase/` | `App.swift`（菜单栏图标、菜单、当前资料库、拖放、测试钩子），`MainWindow.swift`，`Tray.swift`（面板），`Welcome.swift`（第一次的小窗口），`Settings.swift`，`Watcher.swift`，`Server.swift`，`Files.swift`、`QuickLook.swift`、`Thumbnails.swift`（文件像在访达里），`Config.swift`（家目录、子进程、小配置、日志） |
| `Resources/` | `Info.plist`；注入网页的 `shell.js`；服务启动时带上的 `parent-watch.mjs` |
| `Icon/` | 应用图标和菜单栏图标，见 [`Icon/README.md`](Icon/README.md) |
| `build.sh`、`verify.sh`、`measure.sh`、`experiments/` | 构建、检查、测量、实验，见下 |

## 构建

```sh
app/build.sh --node <一个独立的 node>      # 或设 PNEUMA_BASE_NODE；都不给就用 PATH 上的 node
open "app/dist/Pneuma Base.app"
app/build.sh --node <…> --dist             # 另打一个 zip，给别人下载
```

`build.sh` 一条命令做完：核对 Node，`pnpm build`（没装依赖就先 `pnpm install --frozen-lockfile`），`swift build -c release`，用 `scripts/pack-dist.mjs` 打出命令行的包文件、解开放进应用，拼成 `app/dist/Pneuma Base.app`，最后用 `codesign --sign -` 做本机签名。`--dist` 再用 `ditto -c -k --keepParent` 打成 `app/dist/Pneuma-Base-<版本>-<架构>.zip`。缺了 Node 或命令行的应用，一启动只弹一句「Pneuma Base 不完整」。

Node 要合两条，`build.sh` 都核：不低于命令行的 Node 下限（`packages/cli/src/node-floor.ts`）；只依赖 macOS 自己的库（`otool -L` 里只有 `/usr/lib/` 和 `/System/Library/`），因为它要在什么都没装的机器上跑。nodejs.org 的构建合。Homebrew 的不合：它的 `node` 只有约 130 KB，其余在 `libnode` 和几十个 Homebrew 的动态库里；`build.sh` 拒绝它，并给出同版本的 nodejs.org 下载地址。应用是构建时那个 Node 的架构（`build.sh` 印出的 `built …` 一行和 zip 的名字里都有 `lipo -archs` 的结果）；存储的程序不是 `darwin-arm64` 的，`build.sh` 拒绝打包。

应用里有什么（大小随构建略有不同）：

| 位置 | 是什么 | 大小 |
| --- | --- | --- |
| `Contents/MacOS/Pneuma Base` | 外壳 | 约 1 MB |
| `Contents/MacOS/node` | 构建时给的 Node，原样拷进来；有签名的保留它自己的签名，没有的给它一个本机签名 | 约 117 MB |
| `Contents/Resources/cli/` | 命令行的包：`dist/bin.js`，`node_modules/@pneuma-base/` 里的内核、sdk、管理界面和五个内置插件，`templates/`、`PLUGINS.md`、`LICENSE`；内核的 `bin/` 里是本机文件夹提供者 `pneuma-base-core`（约 5 MB）、契约测试的程序 `pneuma-base-contract`（约 2 MB）和写着 `darwin-arm64` 的 `platform` | 约 11 MB |
| `Contents/Resources/` 其余 | 图标（`AppIcon.icns`、`Assets.car`）、`shell.js`、`parent-watch.mjs` | 约 1.5 MB |

合起来约 130 MB，zip 约 45 MB。能变小的地方：

- `strip -x` 去掉 Node 的本地符号：122.6 MB 变成 98.4 MB，命令行照样能跑，zip 只小约 4 MB（量过）。代价是 Node 自己的签名没了，要重签，崩溃时的调用栈没有名字。没有做。
- 自己编一个 Node，只带少量 ICU（`--with-intl=small-icu`）、不带调试器（`--without-inspector`）。估计再小 25 到 30 MB（推测，没有编过）；代价是要维护一条 Node 的构建，`Intl` 只认英文。
- 同时支持 Intel 要把两个 Node 合成一个通用的，Node 那一份翻一倍。

用 SwiftPM 而不是 Xcode 工程：没有 `.xcodeproj` 这种难审阅的文件，`swift build` 在命令行上每次得到一样的结果，不用打开 Xcode。代价是 `.app` 由脚本拼装，资源文件不走 SwiftPM 的资源机制。

## 运行

### 家目录、启动参数、子进程

应用给它起的每个子进程设 `PNEUMA_BASE_HOME`：启动参数 `--home`，否则环境变量 `PNEUMA_BASE_HOME`，否则 `~/.pneuma-base`，和从包安装的命令行用的是同一个。应用自己的东西在它的 `app/` 下：`libraries.json`（认识哪些资料库 `libraries`、当前是哪个 `current`、监看按资料库记的游标 `cursors`，和这台机器的设置 `ownerFiles`、`pathLink`、`appearance`），`app.log`（每件事一行，带时刻和启动以来的秒数，检查和测量读它），`cache/thumbnails/`。窗口的位置和大小由系统记在 `dev.pneumabase.PneumaBase` 的偏好里。

其余启动参数：`--library <文件夹>` 把它记成当前资料库；`--open` 在有资料库时启动就打开窗口；`--hooks <名字>` 打开测试钩子。例如 `open "app/dist/Pneuma Base.app" --args --home /tmp/试一试 --library ~/某个库 --open`。

子进程拿到的环境是固定的：`PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin`、`PNEUMA_BASE_HOME`，和启动者的 `HOME`、`USER`、`LOGNAME`、`TMPDIR`、`LANG`。启动者的 agent 会话变量不传下去，所以从 agent 的终端里打开应用，命令行也不会把应用当成 agent。应用每次运行是一个场景（`--session` 带同一个号），这次拖进来的和监看登记的归在一起。

服务是子进程 `node --import parent-watch.mjs bin.js view <库> --no-open`，应用握着它的标准输入；应用不管怎么结束，管道一断服务就退出，所以应用被杀也不留下服务。应用从服务的输出里读页面地址（`http://127.0.0.1:<端口>/?token=…`）。服务意外退出时，从半秒起每次加倍、最多 10 秒后重起；端口和令牌会变，窗口照新地址重新载入，页不变。退出应用时停掉它，两秒还没退就杀掉。

### 本机的命令

应用每次启动都跑一次自带命令行的 `launcher install`，让本机的命令 `$PNEUMA_BASE_HOME/bin/pneuma-base` 指向应用里的 Node 和命令行；内容没变就不写，不要管理员权限，不改 PATH。连接 Agent 时写进去的都按绝对路径指这个脚本，所以应用移动了位置或换了新版，下次启动后已连接的 agent 照样能用。脚本是什么、什么时候写，见 [`ARCHITECTURE.md`「连接一个 agent」](../ARCHITECTURE.md#连接一个-agent)。

macOS 把从解压的地方直接打开的下载应用放在一个临时的位置运行（App Translocation），退出后那个位置就没了，本机的命令指向那里就会断。应用的路径里有 `/AppTranslocation/` 时，先弹出「请将 Pneuma Base 移动到「应用程序」文件夹后再打开」，按钮是「退出」和「暂不移动」。

### 第一次打开

还没有资料库时只出一个小窗口：两句话，问资料库放在哪。可选的出自 `storage list --json`：这台机器装了的存储提供者（内置的写作「本机文件夹」），和官方的、未安装的（标「· 未安装」）。只有一个时不出弹出菜单，按钮就是「选择文件夹…」；选了官方未安装的，按钮是「安装并选择文件夹…」，先跑 `storage install <仓库>`；答的地址不是文件夹的，按钮写着「<名字> 的地址不是文件夹」，不能点。

下面的「安装其他存储…」问一个 GitHub 仓库（`owner/repo` 或 `owner/repo@版本`），跑 `storage install`。命令行答的信任的话（存储提供者以当前用户身份运行、可访问资料库中的全部内容，仓库、版本、校验和）原样放进一个对话框，点「安装」就照命令行给的那条命令、带着那个校验和再跑一次。

选的文件夹不是资料库（存储的 `declaration.read` 答不出声明）就 `init <文件夹>`，选了提供者时加 `--provider <名字>`；然后主窗口打开在它的首页上，之后应用待在菜单栏里。没有资料库时点菜单栏图标，也是这个小窗口。

### 窗口

窗口是带原生外框的网页：标题栏透明，内容铺满，窗口不透明，网页画自己的底和边栏，地址带 `shell=mac`。缺省 1180 × 760 点，最小 720 × 440。

- 网页报内容就绪时窗口才显示，最多等 1 秒，所以没有白屏。窗口开着时有 Dock 图标；关掉窗口，Dock 图标消失，网页视图随之销毁，不占网页进程，也没有网页在轮询。再打开时重新载入，回到关之前的那一页；换了资料库就回到首页。
- 网页用 `data-drag` 标出的区域能拖动窗口；在那里双击，照系统设置缩放、最小化或什么都不做。
- 网页上的右键菜单只在输入框、链接和选中的文字上出现，浏览器的几项（重新载入、后退、前进、检查元素、在新窗口打开、下载）去掉了。指向别处的链接在默认浏览器里打开；网页给的下载弹出系统的存储面板。网页进程意外退出时重新载入。
- 要确认、不用填的动作是窗口上的系统表单：危险的按钮是红的，回车不按它，Esc 和「取消」什么都不做。
- ⌘F 在工具栏里放一个搜索框（「在本页中查找」），交给 `WKWebView.find`：回车找下一个，⇧回车找上一个，Esc 收起；找不到时字变红。

| 菜单 | 项 |
| --- | --- |
| Pneuma Base | 关于、设置… ⌘,、直接拷入的文件记为我添加、隐藏 ⌘H、隐藏其他 ⌥⌘H、全部显示、退出 ⌘Q |
| 文件 | 新建或打开资料库… ⇧⌘O；打开 ⌘O、快速查看 ⌘Y、在访达中显示 ⌘R、复制路径 ⌥⌘C、重命名（对网页里选中的条目，没选中时灰着）；关闭窗口 ⌘W |
| 编辑 | 撤销 ⌘Z、重做 ⇧⌘Z、剪切、拷贝、粘贴、全选；查找… ⌘F、查找下一个 ⌘G、查找上一个 ⇧⌘G |
| 显示 | 列表 ⌘1、图标 ⌘2；后退 ⌘[、前进 ⌘]、上一级 ⌘↑；重新载入 ⌥⌘R；进入全屏幕 ⌃⌘F |
| 窗口 | 最小化 ⌘M、缩放、前置全部窗口 |

### 菜单栏图标和面板

图标是一个带平底的环，有事等所有者决定时左上角多一个点，悬停提示写着几项待处理。点数的是 `show home --json` 里所有 `asks` 块的件数。应用每 2 秒问一次服务的摘要（`/api/rev`），窗口开不开都问；摘要变了就数一次，添加条目后数一次，另外每分钟一次；面板报来的数也用。

点图标是面板：一块挂在图标下面、居中对着它的无边框面板，和系统自己的菜单栏小程序一样，没有箭头，圆角，一道细边，有阴影。里面是同一个服务给的网页（`shell=mac&panel=tray`），排法见「壳里的网页」。宽 340 点，高照网页报的内容高，至少 120 点，最多 600 点，也不超过菜单栏下面的空间，再长网页在里面滚。点别处、按 Esc、再点图标都关上它。它的网页视图第一次打开面板时才造，之后留着，所以再打开是立刻的；面板不显示时网页不问服务。面板头上的「···」是应用的菜单：外观、资料库、设置…、退出 Pneuma Base。

右键图标（或按住 Control 点它）是资料库的菜单：认识的资料库（当前的打勾，悬停提示是路径）、新建或打开资料库…、打开主窗口、外观、直接拷入的文件记为我添加、设置…、退出 Pneuma Base。

### 拖放和选文件

拖到窗口任何地方或菜单栏图标上的文件和文件夹，和网页里「选择…」弹出的面板选的（文件和文件夹都行，可多选），都经命令行以所有者导入的添加：`put <文件> --to <位置> --imported --by owner --source <来源> --note 拖入的文件`。

- 添加到窗口正在看的文件夹（地址里的 `view.dir`，资料库页和文件页都用它），没有就是资料库根的 `inbox/`。拖着时窗口上写「松开以添加到 <文件夹>/，标记为我导入」，菜单栏图标高亮。
- 同名时按 Finder 给副本起名的写法加「 2」「 3」；哪个名字空着问存储的 `glance`，一次问 50 个。
- 来源是 macOS 记下的下载地址（文件上 `com.apple.metadata:kMDItemWhereFroms` 的第一项，进资料库前读），没有就是它原来所在文件夹的名字。
- 添加之后，和监看登记了东西之后一样：窗口开着时是网页里的一条提示，关着时是一条系统通知，点它打开窗口。从窗口自己拖出去又拖回来的不算添加。没有当前资料库时什么都不收。

### 文件像在访达里一样

网页说库内路径，外壳问存储的 `glance` 并按名字要 `fs.path` 这个字段（[`STORAGE.md`](../STORAGE.md) 第 7 节），得到这台机器上的文件。存储给不出本机文件的位置跳过，记一行日志；先用 `read` 把内容取到临时文件这一步没有做，本机文件夹总有本机文件。

- 快速查看是系统的面板，给一组文件，停在指定的那个上。面板拿着键盘时：空格关掉它；只有一个文件时方向键交还网页，网页换选中项再要一次，面板跟着；几个文件时面板自己在它们之间走。快速查看拿着键盘时窗口仍算前台，网页不调淡。
- 打开、打开方式、在访达中显示用 `NSWorkspace`；打开一个目录就是在访达里打开它。复制路径把绝对路径写进剪贴板，一行一个。
- 右键菜单是系统的菜单：先是外壳的几项（打开、打开方式、快速查看、在访达中显示、复制路径），再是网页给的项，危险的第一项前面一条分隔线。「打开方式」列系统给的程序，默认的在最前、标「（默认）」，其余按名字排，同一个程序只列一次。
- 缩略图（图标视图）由系统的缩略图服务做，一次最多 50 个，同时做 4 个。目录给文件夹的图标；只有占位的文件不读内容，给它那一类的图标；系统做不出的也给类型的图标。缓存在 `$PNEUMA_BASE_HOME/app/cache/thumbnails/` 下按资料库分的目录里，按位置、令牌和像素取名；用到就更新修改时间，30 天没用到的在启动时删。
- 拖出去：网页说拖的是哪几行，外壳用系统的拖动拖出真的文件，给别的应用的是副本。
- 在访达中显示网页格里写的本机路径，只认当前资料库的文件夹和它里面的路径。
- 再打开那次对话，按次序试：有程序认的链接，打开链接；记下的目录还在，在临时目录的 `dev.pneumabase.reopen/` 下写一个 `.command` 文件（`cd` 进那个目录，`exec` 那条命令；之前写的删掉），交给收它的程序，也就是默认的终端；对话文件还在，在访达中显示它；都不行时什么都不做。

这些只是外壳的，不改资料库，命令行和 agent 那边没有对应的。右键菜单里网页给的归档、移动、重命名是资料库的动作，走网页按钮的那条路，经命令行。

### 设置

「Pneuma Base › 设置…」（⌘,）、面板的「···」或右键菜单打开设置窗口，都是这台机器的设置；设置页的「本机」一节是同样几项，值由外壳给。

- **外观**：跟随系统（缺省）、浅色、深色，面板的「···」和右键菜单里也能选。它设的是应用的外观（`NSApp.appearance`），窗口、面板、系统的表单和菜单跟着变，两个网页视图的 `prefers-color-scheme` 也跟着它，一起变，不用重启。
- **直接拷入的文件记为我添加**：缺省开，菜单里也有这一项。关着时监看照样听，不登记。
- **安装命令行工具**：缺省关。打开时，在选的文件夹里放一个叫 `pneuma-base` 的符号链接，指向本机的命令。可选的是所有者 PATH 上能写的文件夹，PATH 问登录 shell 要（`$SHELL -ilc`），三秒没答复就用应用自己的。那里已有一个不是这里放的 `pneuma-base`，不动它，说出来。本机的命令所在的文件夹已经在 PATH 上时，只说这一句。一个能写的都没有时，给出要加进 shell 配置文件（zsh 是 `~/.zshrc`，bash 是 `~/.bash_profile`）的那一行和「复制」按钮，不写文件。关掉时，链接还指向本机的命令才拿走。
- **登录时启动**：缺省关，用 `SMAppService.mainApp`。系统要所有者在「系统设置 › 通用 › 登录项」里允许时，设置里说这一句。

## 监看

监看是存储自己的订阅，应用没有自己的事件流。换到一个资料库时，应用用 `storage list --library <库> --json` 问它用哪个提供者、程序在哪，起这个程序的常驻模式（`serve --root <库>`，应用的子进程），发一条 `subscribe`，带这个资料库上次听到的游标，所以应用没开着时进来的文件，下次打开也听得到。监看的 `probe` 和外壳的 `glance` 都经这个进程问；它没在跑时 `glance` 起一次提供者的程序问，`declaration.read` 总是这样问。提供者意外退出时，从半秒起每次加倍、最多 10 秒后再起它，从记下的游标接着订阅。退出时关掉它的输入，提供者取消订阅后自己退出，两秒还没退就停掉它；应用被杀，管道断了，它一样退出。

「直接拷入的文件记为我添加」开着时，监看按这几条做：

1. 只看上次看过之后订阅报来过的位置；`PNEUMA-BASE.md` 和归档区（`_archive/`）不算。
2. 等资料库安静 3 秒再看，不把所有者还在复制的文件拿走一半。
3. 看就是读溯源插件的状态页，三种各读一次：`show ledger.status --kind unowned|closed|changed --json`。不用 `check`：它会记一条「已查看资料库变化」，把首页的新动态标成已读。
4. `unowned`（未登记）里报来过的文件（它或它所在的文件夹报来过）：`put <路径> --imported --by owner --observed --note 自动登记`；存储 `glance` 的 `macos` 面有 `where_from` 时加 `--source <下载地址>`。`changed`（外部修改）里报来过的：`say revised <路径> --observed`。
5. `closed`（未登记的目录）里报来过的（它自己或里面的东西）：先在订阅的那个进程上 `probe`，预算 500 项。没超出、顶上没有项目标记（`package.json`、`.git` 这些）的，同样 `put` 登记成一个条目；别的不动，它就是溯源插件在首页上问所有者的那一句。一个八万个文件的项目目录因此是一句问话，不是八万次登记。
6. 在这次看和这次放之间别人登记了它，`put` 答已登记，只记一条备注。

一次添加正在写时，内核在存储里占着它要改的位置，等插件都记下才放开，溯源插件的状态页不报被占着的位置。所以「这个文件有没有人登记」只问溯源插件，监看自己不判断，也不会把 agent 正在放的文件当成所有者的。agent 违反说明、在资料库里直接写文件又过了几秒才登记的，监看先把它登记成所有者导入的（检测到）；agent 之后说的来源换掉检测到的那条（[`ARCHITECTURE.md` 第 8 节「溯源与核对」](../ARCHITECTURE.md#8-自带的插件)）。

## 检查

### `verify.sh`

`app/verify.sh` 驱动构建好的应用（先 `app/build.sh`），沿新所有者走的那条路走一遍，每一项印 `ok` 或 `FAIL`，有 `FAIL` 时退出码不是 0。它用临时的 `HOME`（里面放假的 `~/.claude` 和 Claude Desktop 的配置目录）和临时的 `PNEUMA_BASE_HOME`（`open -n --env`），不读不写这台机器上真的 agent 配置和资料库；命令行用应用自带的 Node 和命令行，PATH 上只有系统工具。它起的那一份应用带自己的钩子名（`verify<进程号>`），按钩子名找进程、停进程，不碰别的 Pneuma Base。核对的几组，每一项见脚本：

- 第一次打开和添加：小窗口、应用里带的存储程序、本机的命令、建成资料库，服务和监看是应用的子进程；拖到窗口和菜单栏图标的去处、同名的起名、来源；监看登记直接写进来的文件和下载地址、记下直接的改动，小文件夹是一个条目，八万个文件的项目目录只是一句问话；agent 放的都还是 agent 的。
- 文件像在访达里：外壳这一侧的每一样，和网页那一侧真的发出这些消息（点、键、双击、拖、右键、图标视图、继续对话、外部修改的显示），框架发的消息不理。
- 连接 Agent：假的 Claude Code 和 Claude Desktop，技能里的命令行和 MCP 条目在 `env -i` 下照样能用、做的事是 agent 的；本机的 endpoint、配对、MCP over HTTP。
- 菜单栏、外观、设置：图标上的点、面板的内容和高度、外观的三种选法和记住、系统表单和存储面板；两个方便的开关缺省关，安装命令行工具放上又拿走链接。
- 退出和搬家：退出和 `kill -9` 之后不留进程；把应用拷到别处，本机的命令跟着改、连接照样能用，移走后 `agent list` 说出来，再开原来的应用修好；再次启动时外观还在，30 天没用的缩略图删掉。

设了 `PNEUMA_BASE_SHOTS=<文件夹>` 时，顺路给几个窗口和页面各拍浅色、深色两张放进去。`app/verify.sh pictures <资料库> <文件夹>` 只拍图：那个资料库上窗口的首页、活动、设置、Agent 页、收起的边栏和面板，各浅色、深色。

### `measure.sh`

`app/measure.sh <资料库> [轮数]` 在一个资料库上量几轮，缺省三轮。每轮量启动（从 `open` 到应用日志里的 `status item shown`，另报从内核起进程算起的时间）；打开窗口到网页画出第一帧（`page drawn`），第一次和关掉再开的第二次；空闲时各进程的内存（`footprint`）和 60 秒里的 CPU，窗口开着（移到屏幕角落）和关掉 75 秒后各一次。量的进程是应用、服务的 Node、网页进程和 WebKit 的 GPU、网络进程，不含两个存储提供者；60 秒里退出了的写 `exited`。它用临时的 `PNEUMA_BASE_HOME`，钩子名是 `measure`。每轮开始前它按名字退出正在跑的 Pneuma Base，你自己开着的那一份也会被退出；量完删掉系统记下的窗口位置。

### `experiments/put-race.mjs`

查监看会不会把 agent 正在放的条目当成所有者的，可以重跑：`PNEUMA_BASE_HOME=<家目录> node app/experiments/put-race.mjs <模式> <资料库> [次数]`。它用这个仓库的 `packages/cli/dist/bin.js`，先 `pnpm build`。

- `window`：agent 一个接一个地放文件，量文件出现到第一条新事实之间的空档。
- `marks`：不开应用，agent 一个接一个地放文件，两个读者背靠背地读状态页，和监看读的一样；放着的文件不该出现在「未登记」里。同时直接写进去的几个文件是对照，读者要列出它们。
- `app`：应用开着，用同一个家目录、在这个资料库上。agent 按说明从资料库外放文件（有小的，有 50 MB 的），每次前停一个监看等安静那么久，让它的看落在放上；再让 agent 在资料库里直接写文件、隔几秒才登记。最后读每个文件的来源，和应用日志里监看的看和放重叠了几次。

### 测试钩子

只在启动时带 `--hooks <名字>` 才有：应用听名为 `dev.pneumabase.hooks.<名字>` 的分布式通知，通知的 object 是一条命令（`动词` 或 `动词:参数`）。命令做的是一个人在应用里做的事（开关窗口、退出、打开资料库、经拖放的同一段代码添加文件、点图标、选菜单的一项、按表单的按钮、选外观、开关设置），和检查要读的东西（进程号，窗口、面板、小窗口、设置窗口的文字或图，在窗口的网页里跑一段 JavaScript 的结果；检查也用它替网页给外壳发消息）。完整的表在 `App.swift` 的 `listenForTestCommands` 上面。带钩子时菜单不弹出来（只记下各项，等 `menu-pick:`），拖出去不真的开始，伸到应用外面的事（打开、在访达中显示、写剪贴板、开终端）只在日志里记一行 `opener: …`。

## 哪里还不像原生

原生的：窗口和外框（红黄绿按钮、全屏、拼贴、调度中心、位置大小记住）、菜单栏图标和菜单、主菜单和快捷键、⌘F 的搜索框、快速查看、文件的右键菜单和「打开方式」、拖出去、缩略图、确认的表单和存储面板、滚动（WebKit 用系统的惯性滚动和浮动滚动条）、文字渲染、外壳里网页用的系统字体、选中文字时的右键菜单。下面这些还看得出是网页，或者还不像正常的应用：

| 哪里 | 现状 | 能不能补 |
| --- | --- | --- |
| 强调色 | 网页没有自己的强调色：主要按钮近黑，蓝色只给键盘焦点和「进行中」，不跟系统设置里的强调色和高亮色 | 能。外壳里把 `--focus` 换成 WebKit 认的 `AccentColor` |
| 控件 | 分段选择、按钮、焦点框、悬停高亮都是网页画的；系统的边栏没有悬停高亮，焦点框也不是这个样子 | 大部分能靠外壳里的 CSS 拉近，做不到一模一样；要一模一样得用原生控件 |
| 打开窗口的速度 | 关窗口时网页视图随窗口销毁，再打开要重新起网页进程、取页面和数据，内容就绪之前窗口不显示（最多等 1 秒）；原生窗口几乎是立刻的 | 部分能。关窗口时留着网页视图，第二次打开就是立刻的；代价是一个网页进程的内存和窗口关着时的轮询 |
| 刷新 | 窗口和面板的网页每 2 秒问一次服务的摘要，变了才重取 | 能。外壳订阅着存储的变化，可以推给网页，不用轮询 |
| 进程 | 窗口开着时有七个进程：应用、服务的 Node、两个存储提供者（监看起的和服务起的）、网页进程、WebKit 的 GPU 进程和网络进程；同样功能的原生应用只有一个 | 不能根本改变。Node 和 WebKit 的几个进程是这个方案的底数 |
| 通知 | 本机签名的应用，系统不允许它发通知（应用日志里是 `app: notifications not allowed`），所以窗口关着时，拖放和监看的那句话看不到 | 和方案无关，正式签名之后按正常的应用对待 |

## 发给别人

`app/build.sh --node <…> --dist` 在 `app/dist/` 里打一个 zip，约 45 MB。应用只有本机签名（ad hoc），没有开发者证书，没有经过 Apple 公证。下面的步骤按 Apple 的说明写，没有从网上下载实际走过一遍。

别人下载之后，在 macOS 15 和 26 上第一次打开要做的：

1. 双击 zip 解开，把「Pneuma Base」拖进「应用程序」文件夹。不拖就打开，macOS 让它在一个临时的位置运行，应用会先提醒（见「本机的命令」）。
2. 双击打开。系统说 Apple 无法验证它是否含有恶意软件，只给「完成」和「移到废纸篓」。点「完成」。按住 Control 点「打开」绕不过这一步。
3. 打开「系统设置 › 隐私与安全性」，往下翻，在说 Pneuma Base 被阻止的那一行点「仍要打开」，输入密码或用触控 ID。
4. 再双击一次，在弹出的对话框里点「仍要打开」。之后每次都直接打开。

另外：通知发不出去（见「哪里还不像原生」）；登录时启动，系统答不答应没有验证过；只能在和构建的机器同一种芯片的 Mac 上运行，也就是 Apple 芯片。

用开发者证书签名并公证之后：第一次打开只问一句「这是从互联网下载的，确定要打开吗」，不用去系统设置；通知和登录项按正常的应用对待。不变的是：没拖进「应用程序」就打开时照样在临时位置运行，那句提醒照样有用。要做的是：加入 Apple Developer Program，拿一张「Developer ID Application」证书；`build.sh` 里的两次 `codesign` 改用这张证书，加 `--options runtime` 和时间戳（Node 在加固的运行时里要 `com.apple.security.cs.allow-jit`，nodejs.org 的 Node 自己的签名带着它）；再用 `xcrun notarytool submit` 送去公证，`xcrun stapler staple` 把结果钉在应用上，最后打 zip。
