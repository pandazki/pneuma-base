# 部署库 `deployPlugin`

`@pneuma-base/sdk/kit` 里的部署库：给它一个插件名和一种或几种目标，它交回一个完整的部署插件。插件作者怎样用它、怎样写一种目标（`TargetAdapter`、`Target`、`view`、look），它给的命令和页的大样，都是插件规范的一部分，在 [`PLUGINS.md`「开发包里的库」](../../../../../PLUGINS.md#5-开发包里的库)。这里写库自己怎样做：决定、状态、对账、发布前的复制、站点名、存放、答复和页面。

自带的 `deploy` 插件是 `deployPlugin('deploy', [cloudflareTarget, selfHostedTarget, folderTarget, commandTarget])`，见 [`packages/plugin-deploy`](../../../../plugin-deploy/README.md)。

## 文件

| 文件 | 内容 |
| --- | --- |
| `plugin.ts` | `deployPlugin`：从插件名和目标拼出插件对象，钩子、`onAsks`、`onRemove` |
| `target.ts` | 目标的接口 `TargetAdapter`、`Target` 和 `defineTarget` |
| `model.ts` | 决定和状态，纯函数：`want`、`plan`、`statusOf`、`siteName` |
| `reconcile.ts` | 对账：为一个声明过的条目读资料库和目标，按 `model.ts` 决定，做两边的差 |
| `content.ts` | 经存储读一个条目：复制到缓存目录下的临时目录，算内容编号 |
| `facts.ts`、`folded.ts` | 记录处 `facts/` 里的事实，和从事实推出的行 |
| `commands.ts` | 所有者命令和它们的参数表 |
| `connect.ts` | 连接目标的动作和命令行：找到的一下连接、每组和每种的对话框、改一个设置、断开连接 |
| `views.ts` | 页、条目面板里的一节，和目标加内容的地方 |
| `words.ts` | 给 agent 和所有者读的字：状态、一行的样子、查的节、放和归档之后的话、认知段 |

## 一个决定

库只做一个判断：目标上**该有**什么。输入是三样：开关、是否在归档区、资料库里它的路径上有没有条目。

| 开关 | 在归档区 | 路径上有条目 | 目标上该有 |
| --- | --- | --- | --- |
| 已开启 | 否 | 有 | 当前内容，放在当前路径的站点名下 |
| 已开启 | 否 | 没有 | 什么都没有 |
| 已开启 | 是 | 不看 | 什么都没有 |
| 已关闭 | 不看 | 不看 | 什么都没有 |

代码里是 `model.ts` 的 `want`。对账（`plan`）拿「该有」和「目标上有」的比：该有的站点名下内容不同或没有，就发布；这个条目在目标上别的站点名下的（移动之前的旧名），在发布成功之后取消发布；该有的是什么都没有，就把它的站点全部取消发布。两边一样就什么都不做，所以对账跑几遍结果都一样。

`<名字> sync`、发布、取消发布、添加、移动、归档、取消归档之后，都是对受影响的那个条目跑同一个对账。`<名字> sync` 对全部声明过的条目跑，并把当前目标上不属于任何声明的站点取消发布（声明随归档区一起被清掉的那种）。

## 状态

状态是「该有」和「目标上有」的纯函数（`statusOf`）：两边一致时按原因叫 已发布、未发布、已归档、条目缺失；不一致时，该有内容叫 待发布，该是空的叫 待取消发布。

| 状态 | 开关 | 在归档区 | 路径上有条目 | 目标上 |
| --- | --- | --- | --- | --- |
| 未发布 | 已关闭 | 否 | 不看 | 没有它的站点 |
| 已发布 | 已开启 | 否 | 有 | 恰是当前内容，在当前站点名下 |
| 待发布 | 已开启 | 否 | 有 | 别的内容、没有，或还在旧的站点名下 |
| 已归档 | 不看 | 是 | 不看 | 没有它的站点 |
| 待取消发布 | 已关闭，或在归档区，或路径上没有条目 | | | 还有它的站点（上次取消发布失败） |
| 条目缺失 | 已开启 | 否 | 没有 | 没有它的站点 |

会报告自己在服务什么的目标读不到时（`serving` 抛错），状态是 **状态未知**：这次什么都不发布、不取消发布，`check` 和页面说读不到的原因。

## 状态 × 操作

每一格是：这次操作之后对账做了什么 → 目标答应时的状态（目标失败时的状态）。发布、取消发布是所有者命令；内容修改是 `put` 添加了不同的内容，或登记了在工具外改过的内容；移动是 `put <库内路径> --to <库内路径>`。格里的「发布」都照 `plan`：目标上那个站点名下已是当前内容时不发布；「取消发布旧名」只撤别的站点名下的。

| 状态 ＼ 操作 | 发布 | 取消发布 | 内容修改 | 归档 | 取消归档 | 移动 |
| --- | --- | --- | --- | --- | --- | --- |
| 未发布 | 发布 → 已发布（待发布） | 不动 → 未发布 | 不动 → 未发布 | 不动 → 已归档 | 内核什么都不动（本来就在原处）→ 未发布 | 记下新路径，不动 → 未发布 |
| 已发布 | 不动 → 已发布 | 取消发布 → 未发布（待取消发布） | 发布新内容 → 已发布（待发布，目标上还是旧的一版） | 取消发布 → 已归档（待取消发布） | 内核什么都不动 → 已发布 | 在新站点名下发布，再取消发布旧名 → 已发布（待发布，旧名照旧已发布） |
| 待发布 | 发布 → 已发布（待发布） | 取消发布它在目标上的站点 → 未发布（待取消发布） | 发布 → 已发布（待发布） | 取消发布它在目标上的站点 → 已归档（待取消发布） | 内核什么都不动；发布 → 已发布（待发布） | 在新站点名下发布，再取消发布旧名 → 已发布（待发布） |
| 已归档 | 记下开关，不动 → 已归档 | 记下开关，不动 → 已归档 | 不适用：归档区里的条目不能添加（`outside-library`） | 内核什么都不动 → 已归档 | 开关已开启：发布 → 已发布（待发布）；开关已关闭：不动 → 未发布 | 不适用：归档区里的条目不能移动（`outside-library`） |
| 待取消发布 | 原因是开关已关闭：发布 → 已发布（待发布）；原因是归档或条目缺失：再取消发布 → 已归档 / 条目缺失（待取消发布） | 再取消发布 → 未发布 / 已归档（待取消发布） | 原因是条目缺失：发布 → 已发布（待发布）；原因是开关已关闭：再取消发布 → 未发布（待取消发布） | 再取消发布 → 已归档（待取消发布） | 原因是归档：开关已开启则发布 → 已发布（待发布；目标上已是当前内容时不用发布，目标失败也是已发布），开关已关闭则再取消发布 → 未发布（待取消发布）；否则内核什么都不动，再取消发布 | 原因是开关已关闭：记下新路径，再取消发布旧名 → 未发布（待取消发布）；原因是条目缺失：不适用，没有条目可移动 |
| 条目缺失 | 不动 → 条目缺失 | 不动 → 未发布 | 路径上又有了条目：发布 → 已发布（待发布） | 不适用：没有条目可归档（`no-such-file`） | 不适用：它不在归档区 | 不适用：没有条目可移动（`no-such-file`） |

声明是入口：新的一个条目从 未发布 开始。agent 用 `say deployable` 声明；所有者对没声明的条目 `<名字> publish`，先记声明再记开关。归档区被清掉时（`archive purge`，`onPurged`），先把那里的声明在目标上剩下的站点取消发布，再去掉声明。

[`test/kit-model.test.ts`](../../../test/kit-model.test.ts) 在纯函数上跑这张表里适用的格，它的 `CELLS` 列出跑哪些；[`plugin-deploy/test/kit.test.ts`](../../../../plugin-deploy/test/kit.test.ts) 经真的内核、对一个放在内存里的目标，每种操作跑一格。

## 「目标上有」从哪来

- 目标没有 `serving`：来自插件自己的记录里对当前目标（按 `key`）的发布和取消发布。目标背后被人删掉的站点，它看不见。
- 目标有 `serving`：来自目标。问的是这个条目的路径（归档了就是原来的路径）的站点名，和记录里它的站点名，记录里归另一个还在的声明的站点名不问；一页里全部条目的站点名一起问一次。内容不是 null 的才算目标上有。对账前先把记录对齐目标：目标上有、记录里没有的记成发布（发布到了目标、还没记下就断了的那种），记录里有、目标上没有的记成取消发布。所以 `<名字> sync` 修得好断在一半的发布和被人在目标那边删掉的站点，之后的移动也撤得下旧名。取消发布没人声明的站点时，目标说它没在服务的只记取消发布，不再去撤。

发布前，库把这个条目算进内容的文件复制到缓存目录下的一个临时目录（单个文件保留文件名）。哪些算进内容由存储按内容规则算：带标记的目录要存储的清单（`content` 带 `manifest`，一页至多一万条，一个条目至多 5000 个文件），每条是相对它的路径、指纹和大小，不带 `.pneuma-item`、噪音和它里面的 `.gitignore` 排除的；库不走这个目录。每个文件用存储的 `read` 写到临时目录，再拿它的 sha256 和清单里的指纹比；不同就是读的时候它又变了，不发布，说它正在被改动。核对复制件的编号就是对账时算的，再交给目标；不同也一样不发布。超过 5000 个文件的目录存储答 `too_many`：不发布，也不取消发布目标上的旧版，说它至少有多少个文件；状态是 待发布。

## 站点名

缺省从库内路径算出，内容怎么变都不变：小写，非 `a-z0-9` 的连续字符换成一个 `-`。路径本来就只由小写字母、数字、单个 `-` 和 `/` 组成时就是这个结果（`sites/shop` → `sites-shop`）；否则（大写、中文、别的符号）后面加路径的 sha256 前 6 位，免得两个路径撞名（`网站/首页` → `site-6672c3`）。最长 58 个字符，超了就截断并加那 6 位。两个干净的路径仍可能撞名（`a/b` 和 `a-b`）：后来的那个发布时以「站点名称 … 已被 … 占用」失败，停在 待发布。目标的 `siteName` 可以换掉这条规则，比如加上所有者的前缀。

## 存放

都在 `.pneuma-base/<名字>/` 下，本体：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 目标：`{ format: 1, target: { kind, …目标自己的配置 }, given }`。`given` 是所有者给 `target set` 的开关（没有读进来的密钥），「更换部署目标…」从它开始填，改一个设置时和改的那个一起再跑 `target set`。`<名字> target set` 经存储整份写入，带着读到的那一版的令牌；`<名字> target remove` 删掉它 |
| `facts/` | 记录处的事实，记录库 `facts`：声明、开关、移动、去掉、发布、取消发布，每次一批，写完不动。读不懂的事实原样留着，`check` 里列出 |

换了目标，旧目标上的站点不算，开关已开启的条目都成了 待发布，`<名字> sync` 把它们发到新目标；旧目标上的不会被取消发布。缓存目录里只有发布和算内容编号时的临时目录，用完就删。

## 答复

命令都有参数表，都不是破坏性的；开关和目标只给所有者，因为对外发布是对外的动作（命令表在 `PLUGINS.md`）。`target set` 的活动行按 `host`、`origin`、`admin`、`to` 里先给的那个起名，都没有时是「自定义命令」。

答复说事实，不叫人去跑命令：`已发布 sites/shop → https://…`、`已取消发布 sites/shop。`、`已连接 space.example.com。3 个待发布。`、`已断开连接 space.example.com。2 个已发布的条目未取消发布。`。开关在目标失败时照样记下，答复以 `publish-failed` / `unpublish-failed` 或 `no-target` 拒绝，说开关怎样了、为什么没发布。agent 的添加、移动、归档让目标失败时，添加照样成功，答复的 `problems` 里说它无需重做、发布等所有者运行 `<名字> sync`。

`plugin disable <名字>` 在目标上还有它的站点时拒绝，说有几个已发布、先用 `<名字> unpublish` 取消发布；所有者用 `--force`（界面里是提示上的「仍然停用」）照样停用时，答复列出仍发布在目标上的那些。

## 页面

页 `<名字>.sites`，目标自己的页和它共用导航里的一项。

**未连接目标。** 只有一节「部署目标」：这台机器上找到的每个目标一行，带「连接」（一下就连接，不问什么）；每组目标一行「其他 <组名>」，「连接…」打开对话框，先选组里哪一种，再问那一种的开关，`asked` 的密钥在最后；不在组里的几种在这一节的菜单里，一行都没有时它们就是这几行。

**已连接目标。** 页头是「发布条目」，选一个登记过、还没声明的目录条目（新的在前，最多 200 个，多于 5 个时是可以筛的列表），声明和发布一起做；有条目待发布或待取消发布时另有「重试」（`<名字> sync`）。下面一行是目标，菜单里是「更换部署目标…」、每个设置的「<hint>…」和「断开连接」。再下面每个声明过、在资料库里的条目一行（还待取消发布的归档的也在）：名字点开面板，下面是它所在的文件夹，后面是地址（网址可以点开，都可以复制），最后是开关。没有时写「暂无可部署的条目」。副标题是有地址的有几个：「3 个已发布」。

一行不对劲时带一个标记，悬停说为什么：待发布、待取消发布、条目缺失（警告），状态未知（错误），和目标自己的 `mark`。已发布、未发布什么都不标。目标读不到时，目标那一行标「无法连接」。

**条目面板。** 声明过的条目：标记和原因、地址在一行，目标的字段里有话说的，目标的块；开关在面板的菜单里。还没声明、已连接目标、在资料库里的目录条目：菜单里一项「发布…」，先问「发布 shop 到 space.example.com？」。别的什么都不加；什么都不说的一节不画。

页面按目标的 `refresh` 重取。
