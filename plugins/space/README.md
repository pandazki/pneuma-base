# space: a Pneuma Base plugin that deploys to PneumaSpace

An agent declares a thing in the library deployable with `say deployable <path>`. The owner switches it on and off. While it is on, PneumaSpace serves the library's current content as an app managed by `pneuma-base`. A changed put publishes a new release, a move publishes under the new name and removes the old app, and archiving removes the app. The plugin removes and never purges, so the releases stay and switching on again restores the same content.

It is the deploy kit of `@pneuma-base/sdk` with one target adapter (`src/target.ts`). The adapter identifies content by the sha256 of the bundle tar it uploads, and `serving` answers from what PneumaSpace really has. So `space sync` repairs a publish that died halfway, or an app someone removed in PneumaSpace's console.

The project was generated by `pneuma-base plugin new --kind deploy` and depends on the two Pneuma Base package files only. `FRICTION.md` records what the first version, a fork of the built-in deploy plugin, cost. `FRICTION-RESOLVED.md` records what is left after the rebuild.

## Use

```sh
npm run install-local                                    # build, then pneuma-base plugin install dist
npx -- pneuma-base plugin add space --library ~/base
npx -- pneuma-base space target set --admin http://127.0.0.1:8081 --prefix pb --library ~/base
npx -- pneuma-base secret set space token                # only for a PneumaSpace that is not in local mode
pneuma-base @<grant> say deployable sites/shop           # the agent
npx -- pneuma-base space on sites/shop --library ~/base  # the owner
npx -- pneuma-base space sync --library ~/base           # idempotent; agents may run it
npx -- pneuma-base view ~/base                           # the PneumaSpace page, the board page, and a section in each item's panel
```

- `--public <origin>` sets where sites are reached when that is not the admin host on PneumaSpace's ingress port.
- App name: `<prefix>-<the kit's site name>`, cut to PneumaSpace's 40 characters with six hex characters of the path's sha256 when too long. For example, `sites/shop` becomes `pb-sites-shop`.
- The first publish sets the owner to `service:pneuma-base.<library id>`. The plugin refuses to publish or remove a name that anyone else owns, in any state.
- The pages refresh every 30 seconds, the kit's default for a target that reports what it serves. The board, a page of its own in the navigation, has a card per switched-on site: a live preview, the address, the release, the requests of the last 24 hours with an hourly sparkline from `GET /api/usage?app=` (fetched only when a page is drawn), and the switch.

## Develop

```sh
npm install
npm test                     # build, then conformance against a PneumaSpace in memory (test/fake-space.ts), and the lifecycle and viewer tests against the acceptance stack (skipped when it does not answer)
sh scripts/proof.sh          # the one-command demonstration: a walk-through with curl checks, then the test suite
npm run shots -- <dir>       # screenshots of the board (light, dark) and an item panel, from headless Chrome
PNEUMA_BASE_REPO=../pneuma-base node scripts/count-copied.mjs   # lines of src/ found in the sources the first version copied
```

The lifecycle and viewer tests publish to `SPACE_ADMIN` (default `http://127.0.0.1:18081`). Every app they publish is named `pbs-…` under a prefix of its own, and is removed and purged after. The conformance test needs no service: it sets the target to the test kit's `sandbox.serve` stand-in.
